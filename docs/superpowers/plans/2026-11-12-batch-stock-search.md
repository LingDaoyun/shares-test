# 批量搜股实施计划

目标：输入“东方”等名称关键词，直接展示全 A 股匹配股票的行情卡片和日 K 缩略图。

方案：复用现有新浪股票清单、腾讯行情与日线数据源，新增 `/api/stocks/search` 和 `/batch-search` 页面，不改数据库、不引入依赖。保留当前 master 工作区。真实验收发现原全市场扫描调用在东方财富不可用时超过 120 秒，因此搜索单独缓存完整名称清单，按关键词筛选后仅拉取匹配股票行情。

- [x] 后端：按名称或代码包含关键词匹配，不限制结果条数；完整名称清单缓存 6 小时，只查匹配股票行情；目录读取限制并发并校验完整性。验证全量匹配、空值、缓存、缺报价保留和不完整清单。
- [x] 前端：新增“批量搜股”菜单，关键词搜索后铺开卡片；显示最新价、涨跌幅、换手率、总市值、流通市值、成交额。搜索中、无结果、搜索失败分别展示。
- [x] 图表：复用现有日 K 图组件的 compact 模式，显示最近 60 根前复权日线和成交量；最多四个图表请求并行，单只失败可重试，切换搜索不混入旧结果。保留分时/完整日线入口。已避免每张图返回导致所有卡片重新绘图。
- [x] 验收：定向后端测试、前端测试及构建；本机运行服务更新后，以“东方”搜索实际验证卡片和日 K、窄屏布局及空结果。

结果边界：匹配范围取行情源股票清单；若清单覆盖不完整，页面明确提示，不能声称已经搜全。未知行情字段显示“待补充”，不补零。

2026-11-12 本机验收：前端 470 项测试通过，搜索后端 20 项测试通过，复用日 K 控制器 13 项测试通过；前后端构建通过并更新本机 Docker 服务。真实目录 5580/5580，“东方”30 只与独立分页清单逐只一致，30 张日 K 全部加载。浏览器首次查询 6.752 秒，缓存目录后 API 查询 0.454 秒；390px 窄屏无横向溢出，无匹配词与代码搜索行为正常。运行证据在 `.codex-run/batch-search-20261112/`。
