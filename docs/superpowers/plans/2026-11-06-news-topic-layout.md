# 消息面按主题与发布时间重排

用户要求直接调整现有布局，按主题及发布时间分类。在原消息面中实现，不增加独立模块。

- 左侧主题目录：全部、宏观政策、资本市场、银行保险、外汇大宗、产业公司、海外市场、综合动态。每条消息根据原始标题优先、摘要补充匹配一个主题，未明确匹配的保留综合动态；不调用模型。
- 右侧按北京时间的今天、昨天、具体日期分组，组内发布时间倒序。独立时间窄列；只有日期的原文显示“仅日期”，未知时间单独置后。
- 搜索、消息类别、来源和时间筛选保持；主题计数在这些条件之后、主题筛选之前计算。初始显示60条，分批展开后续60条，筛选改变重置展开数量；已滚动到列表下方时回到结果开头。
- 保留当前刷新、轮询、AI详情与行业解读；来源状态从长列表底部移到主题目录下方。窄屏主题按钮横向排列，列表不溢出。
- 真实数据已重现：全局2000条最新消息上限使官方发布全部被高频媒体挤掉。最小修复为给最新有效官方发布预留最多500条容量，其余容量按时间补满（官方也可使用剩余容量），总量仍2000、30天有效期不变。

验证：分类冲突与北京时间跨日单测；主题与日期分组/联合筛选/分批展开交互测试；原消息与行业兼容测试；后端官方保留回归；隔离发布基线的生产构建；真实页面桌面/窄屏、主题、日期和原文/详情检查。

部署仅替换本次前端文件及FinancialNewsService类，沿用当前运行版本，避免混入其他未提交功能。

## 列表固定高度补充

用户要求列表框保持不动，仅消息内容滚动。右侧改为固定可视高度的纵向布局，顶部筛选、状态与底部加载栏不收缩；中间消息区单独滚动并阻止滚动传递到页面，日期分组头在列表内吸顶。筛选仅重置内部scrollTop，加载更多保留位置。小窗口保留480px最小高度，避免工具栏把内容区挤空。改动限定消息组件，仅发布前端。

相关68项测试及生产构建通过；桌面真实滚动中，列表框top=155、height=740和footerTop=827保持不变，内部scrollTop从0变为729、可见消息改变、页面scrollY保持0。记录位于`.codex-run/news-contained-scroll-20261106/`。
