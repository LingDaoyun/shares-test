# 龙头关联补涨观察 Implementation Plan

> **For agentic workers:** Use subagent-driven-development for the independent data, backend observation, and frontend tasks below. Preserve all existing working-tree changes.

**Goal:** 修正行情缺失与资金榜命名，在现有涨停行业详情中提供可核对的龙头锚点、共同板块、中位跟随观察及隔日价格反馈。

**Architecture:** 复用涨停池和行情客户端，用户选择已封板锚点及供应商确认的所属板块，读取完整成分行情及连续日线；真实验收确认断档后，仅对明确传入的成员补齐整个QFQ窗口。新增观察接口和隔日查询接口；前端在当前浏览器保存首次观察与有限快照。后续用户追加的长上影与14:00持久任务见下文，关联观察本身不增加表或交易指令。

**Tech Stack:** Java 17 / Spring Boot, React / TypeScript, existing PostgreSQL daily-bar reads.

## Global Constraints

- 用户已批准按上述方向实施，沿用现有分支，不创建 worktree，不提交混合修改。
- 初始约定验收由用户负责；用户于2026-10-15明确追加授权自测、构建重新部署及数据库迁移，后续验证按该授权执行。
- 当日资金排名不得称为龙头；封板锚点只是观察对象；供应商共同板块归属不证明事件受益或资金转移。
- 缺失数据与真实零必须分开；日期不一致、历史日期的当前归属、过时盘中报价不能冒充当前可信观察。
- 中位口径：截至看板日前一交易日的连续六个收盘价计算五日收益，同一板块有效样本的收益分位 25% 至 75%；至少五个样本且历史覆盖至少80%才给分位。使用本地同一复权口径，不拼接当天未复权价格。
- 快照为按需刷新；浏览器观察留样保留首次记录，后续刷新不覆盖。隔日仅为下一经日历核实的交易日的价格反馈，非真实成交收益、不以最高价假设卖出。
- 原短线候选评分和五日观察维持原策略；新视图不生成买入指令、不强制用户固定时间买卖。

## Approved addition: 横盘长上影与14:00自动扫描

用户追加要求：将长期横盘后出现长上影的股票加入短线候选，每天下午14:00自动运行，完成后直接加载。

- 独立增加“横盘长上影观察”类型，不把“主力试盘”作为事实，也不受原金叉优先池裁剪。
- 使用前20个完成交易日的本地日线，要求连续、有效且前复权价格基准可核对；具体形态阈值在结果中公开。
- 先筛全市场实时形态再读取对应本地历史，避免额外逐股远程抓K线。
- 增加程序后端交易日14:00定时扫描，官方休市日及未知日历不运行；分别保存原右侧扫描与形态观察的结果/失败。
- 为实现服务重启后仍能加载结果，新增V6小表保存每日任务状态与结果（这是对前文“不增加数据库迁移”的必要范围追加；关联观察自身仍不增加表）。
- 页面打开及轮询只读取保存结果，手动扫描结果与错误不会被自动覆盖，旧日期结果明确标为历史。
- 编写形态、节假日、重复任务、读取不触发扫描、缺数据与页面加载的回归用例；依用户约定不执行。
