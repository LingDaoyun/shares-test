# 短线龙头异动后台观察点设计

## 目标

龙头异动不再依赖用户重复点击扫描建立基线。后台在每个交易日的 09:50、11:30、14:40 自动抓取可靠的全市场快照；人工扫描只读取后台基线、计算当前状态并展示结果，不保存或改写基线。

## 后台观察点

- 时区固定为 `Asia/Shanghai`。
- 默认时点固定为 `09:50`、`11:30`、`14:40`。
- 周一至周五触发后仍由 `TradingClockService` 判断是否休市；休市日直接跳过。
- 后台只获取全市场点时行情、覆盖率和热门方向，不执行 K 线复核、候选评分或完整短线选股。
- 覆盖率不可靠时不保存快照，避免污染后续基线。

## 基线与人工扫描

- 09:50 优先比较上一交易日最后一个可靠观察点。
- 11:30 比较当天 09:50 观察点。
- 14:40 比较当天 11:30 观察点。
- 人工扫描比较最近一个更早的后台观察点；人工扫描自身不落库为基线。
- 新规则版本与旧的人工快照隔离，旧数据不会混入后台观察点。

## 全天累计结果

- 每个后台观察点同时保存快照和该区间检测结果。
- 人工扫描把当天已保存的预警与当前计算合并，按股票和方向去重。
- 历史预警在当前仍满足绝对强势条件时标记“仍在强化”；不再满足时标记“已经回落”。
- 当天较早出现的风险不会因下一次扫描没有新增加速而消失。
- 只有已回落历史信号时，结论显示“今日曾有异动，目前已回落”；当前仍有活跃信号时显示风险提醒。

## 页面表达

- 删除英文 `LEADER ROTATION WATCH` 和内部实现术语。
- 结论只使用四种直白表达：`发现资金切换风险`、`暂未发现明显异动`、`今日异动已回落`、`后台基线尚未建立`。
- 信号显示发现时间、股票、方向、涨跌幅、成交额排名及“仍在强化/已经回落”。
- 后台基线尚未建立时明确说明“不代表没有风险”，并告知下一个后台观察时点。

## 边界

- 龙头风险仍然只展示，不参与候选筛选、评分、排序、仓位、动作、建议或交易计划。
- Codex 不运行测试、回归、浏览器检查或健康检查；代码完成后直接构建并部署，测试由用户完成。
