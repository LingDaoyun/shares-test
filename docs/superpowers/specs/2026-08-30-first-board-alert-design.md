# 盘中首板预警独立页面设计

## 1. 目标

在现有 A 股投研系统内新增一级导航“首板预警”和独立路由
`/first-board-alert`。模块在交易时间内扫描尚未触及涨停、当日涨幅处于
`0%～7%` 的股票，分别展示：

1. `首板潜伏`：上一交易日未涨停；
2. `昨日涨停观察`：上一交易日涨停，今日仍满足候选条件。

模块不另建前端或后端应用，不改变现有“短线右侧”策略，也不执行自动交易。

## 2. 数据结论与规则依据

规则来自 2026-08-14 至 2026-08-28 共 11 个交易日的回溯分析：

- 739 次涨停，其中 607 次首板、132 次连续涨停；
- 抽取 2,243 只股票，形成 9,708 个盘中时点样本；
- 事件时点只保留当时涨幅 `0%～7%` 且尚未触板的股票；
- 对照组为同日未涨停股票；
- 量比使用当前累计成交量相对过去同一时刻成交量的校正结果。

主板且 T-1 趋势、动量全部满足的样本中，10:00 时后续首板股票的实时量比
中位数为 `1.23`，同日对照组为 `0.90`。实时量比不低于 `1.2` 的占比分别为
`53.0%` 和 `23.5%`；实时量比高于 `3.2` 不能作为爆量排除条件。

昨日涨停样本中，主板次日继续涨停 122 次、未继续涨停 498 次。前一日量比
低于 `0.8` 的股票次日继续涨停比例约 `35.3%`，因此昨日缩量涨停应提高排序而
不是排除。该类机会集中在早盘：9:35 仍处于 `0%～7%` 且未触板的成功样本
只有 16 次，10:00 只剩 6 次，午后没有成功样本。

数据来源：

- 东方财富涨停池：`https://quote.eastmoney.com/ztb/detail#type=ztgc`
- 新浪历史分时：`https://quotes.sina.cn/cn/api/json_v2.php/CN_MarketDataService.getKLineData`

该分析描述历史关联，不代表收益保证。规则需要版本化，以便后续用新增样本继续
复核。

## 3. 现有系统内的页面改造

保持现有 `AppShell`、`Header`、胶囊导航、颜色、卡片、表格和弹窗体系。前端只
新增：

- `firstBoardAlert` 页面元数据；
- 导航项“首板预警”，放在“短线右侧”之后；
- `/first-board-alert` 路由；
- `FirstBoardAlertPage` 页面；
- 相应的客户端类型、接口方法和页面状态。

页面从上到下包含：

1. 扫描范围和实时状态；
2. 全市场扫描数、强预警数、观察数、昨日涨停观察数、行情时点；
3. `首板潜伏` 技术表格；
4. `昨日涨停观察` 技术表格。

主板始终启用。创业板、科创板各有一个页面开关，默认关闭；开关状态保存在
浏览器本地。开关打开时分别纳入对应板块，并按各自涨跌幅制度计算触板价格。

## 4. 技术表格

页面不显示综合分数、触发原因或自然语言入选解释。

`首板潜伏` 表格展示：

- 股票名称、代码、行业；
- 现价、涨幅；
- MA10、MA20、MA20 斜率；
- RSI14、MACD 柱；
- 实时量比、昨日量比、近 5 日最大量比；
- 上影线占当日振幅比例；
- 3 日收盘区间；
- 预警等级。

`昨日涨停观察` 使用相同主体列，将上影线占比替换为盘中最大回撤。

点击股票行后复用现有弹窗体系，展示最近 20 日日 K 和成交量图。弹窗仍不显示
触发原因文案。

## 5. 后端模块与接口

在现有 API 应用中新增独立 `firstboard` 模块。它不调用或扩展
`ShortTermService`，只复用低层行情能力、交易时钟和涨停价规则。

模块对前端只提供一个主要接口：

```http
GET /api/first-board-alert/snapshot?includeGrowth=false&includeStar=false
```

响应包含：

- `status`：`PREPARING`、`READY`、`STALE` 或 `UNAVAILABLE`；
- `tradeDate`、`marketTimestamp`、`generatedAt`；
- 板块开关；
- 扫描覆盖统计；
- `firstBoardCandidates`；
- `previousLimitUpCandidates`；
- `dataGaps`；
- `ruleVersion`。

模块的外部 interface 保持为“按板块选择读取最新快照”。日线准备、行情合并、
指标计算、分组和排序都隐藏在模块 implementation 内。

## 6. 两阶段数据流

### 6.1 每交易日 T-1 基础池

每个交易日准备一次全市场 T-1 技术基础池，覆盖主板、创业板和科创板。09:15
定时准备；服务在盘中重启或定时任务失败时，由首次页面请求触发单任务补建。

基础池计算并按交易日缓存：

- 板块、ST/退市状态和有效交易日数量；
- MA10、MA20、MA20 斜率；
- RSI14、MACD 柱；
- 最近 5 日最大量比；
- 前一交易日量比；
- 前一日上影线比例；
- 3 日收盘区间；
- 是否属于上一交易日涨停池。

基础池未完整准备时返回 `PREPARING`，不返回部分候选。缓存以交易日为键；同一
交易日只允许一个准备任务执行。

非交易日打开页面时不禁用扫描：将最近一个交易日作为扫描交易日，以该日收盘行情生成快照，
并将再前一个交易日作为 T-1 技术基线。非交易日不做实时轮询，但基础池处于 `PREPARING`
时页面继续每 60 秒检查，直到上一交易日收盘快照可用。

### 6.2 盘中实时扫描

现有东方财富全市场批量行情增加读取实时量比字段 `f10`。盘中扫描通过一次批量
行情快照取得：

- 最新价、涨幅；
- 开盘价、最高价、最低价；
- 累计成交量、成交额、换手率；
- 实时量比；
- 行情交易日和市场时间。

实时快照与当日 T-1 基础池合并后，依次执行板块、风险、数据质量、涨幅、触板、
技术条件和量比筛选，再分入两个候选区。

创业板和科创板开关只改变快照结果，不重新逐只拉取日 K。全市场日线每天只准备
一次；盘中每分钟不逐只请求分时数据。

## 7. 候选资格

以下情况硬性排除：

- 板块开关未开启；
- ST、退市整理或有效交易日不足 60 日；
- 行情不是本次扫描交易日；
- 最新价、涨幅、最高价或实时量比缺失；
- 当日涨幅不在 `0%～7%`；
- 当日最高价已达到按交易板块计算的涨停价；
- 五项 T-1 技术条件只满足三项及以下；
- T-1 基础数据不完整。

五项 T-1 技术条件为：

1. 收盘价高于 MA20；
2. MA10 高于 MA20；
3. MA20 向上；
4. RSI14 不低于 50；
5. MACD 柱为正。

上一交易日涨停不触发排除，只决定候选进入哪个表格。

## 8. 预警分级与排序

### 8.1 首板潜伏

- `ACCELERATING`：五项全部满足，实时量比高于 `3.2`；
- `STRONG`：五项全部满足，实时量比处于 `[1.2, 3.2]`；
- `WATCH`：恰好满足四项且实时量比不低于 `0.8`，或五项全部满足但实时量比处于
  `[0.8, 1.2)`；
- 实时量比低于 `0.8` 不展示。

长上影和横盘数据只展示，不改变候选资格或等级。最近 5 日出现过 `1.5` 倍以上
放量，只用于同等级排序。

### 8.2 昨日涨停观察

- `REPEAT_ACCELERATING`：10:30 前五项全部满足，实时量比高于 `3.2`；
- `REPEAT_STRONG`：10:30 前五项全部满足，实时量比处于 `[1.2, 3.2]`；
- `WATCH`：恰好满足四项且实时量比不低于 `0.8`，或五项全部满足但实时量比处于
  `[0.8, 1.2)`；
- 恰好满足四项且实时量比不低于 `1.2` 时仍为 `WATCH`，不因量能单项升级；
- 前一日量比低于 `0.8` 时提高同级排序；
- 前一日量比不低于 `3.0` 时降低同级排序，但不排除；
- 早盘实时量比不设上限；
- 实时量比不低于 `1.2` 且盘中最大回撤不低于 `3.0%` 时降低同级排序；
- 市场时间进入 `[10:30, 11:00)` 后等级降低一级：`REPEAT_ACCELERATING` 降为
  `REPEAT_STRONG`，`REPEAT_STRONG` 降为 `WATCH`；
- 市场时间达到 11:00 后，所有候选等级上限为 `WATCH`，不发送强预警通知。

两个表格分别排序。排序顺序为：

1. 预警等级；
2. 满足技术条件数量；
3. 实时量比强度；
4. MA20 斜率；
5. MACD 柱。

`昨日涨停观察` 在预警等级和技术条件数量之后，先按前一日量比规则调整同级顺序，
再比较实时量比、MA20 斜率、MACD 柱；实时量比不低于 `1.2` 且盘中最大回撤不低于
`3.0%` 的候选排在其他条件相同且回撤更小的候选之后。上述修正只改变同级排序，
不产生隐藏综合分数。

## 9. 刷新与页面通知

- 交易时间内每 60 秒请求一次最新快照；
- 后端快照设置短 TTL，并使用单任务锁避免同时重复扫描；
- 页面提供手动刷新；
- 收盘后停止自动刷新，保留当日最后一份快照；
- 新股票首次进入 `STRONG`、`ACCELERATING`、`REPEAT_STRONG` 或
  `REPEAT_ACCELERATING` 时，使用现有页面右上角通知；
- 同一股票同一等级同一交易日只通知一次；
- 从 `WATCH` 升级为 `STRONG`、`ACCELERATING`、`REPEAT_STRONG` 或
  `REPEAT_ACCELERATING` 时允许再次通知；
- 不播放声音，不申请浏览器系统通知；
- 通知去重状态按交易日重置。

## 10. 数据异常处理

- 实时行情整体失败：保留最近一份成功快照并标记 `STALE`，停止发送通知；
- T-1 基础池未完成：返回 `PREPARING`，页面显示基础数据准备中；
- T-1 基础池失败且没有可用缓存：返回 `UNAVAILABLE`；
- 上一交易日涨停池缺失：不猜测候选分组，基础池视为不可用；
- 单只股票关键字段缺失：排除该股票并计入覆盖统计；
- 部分股票异常不影响其他完整股票；
- 页面始终显示预期数量、有效数量、排除数量、行情时点和数据缺口；
- `STALE`、`PREPARING`、`UNAVAILABLE` 状态均不产生页面通知。

另行明确授权，本次实现只提交代码与测试代码，不运行这些验证命令，也不声称已经
通过验证。

## 12. 不在本次范围

- 独立站点、独立后端服务或新部署单元；
- 自动下单、买卖建议或仓位管理；
- 提示音、系统通知、短信或外部消息推送；
- 机器学习预测模型；
- 将首板规则并入“短线右侧”；
- 用首板当天收盘后的信息回填盘中候选；
- 对历史关联作收益或涨停保证。

## 13. 验收口径

完成后的静态业务结果应满足：

1. 现有导航中出现独立“首板预警”入口；
2. 默认只纳入主板，创业板和科创板开关默认关闭并可持久化；
3. 页面同时展示“首板潜伏”和“昨日涨停观察”；
4. 候选严格限制为当时涨幅 `0%～7%` 且尚未触板；
5. 页面只展示技术指标与预警等级，不展示综合分数或触发原因；
6. 盘中自动刷新使用全市场批量行情，不逐只拉取分时；
7. 昨日涨停股票不会被排除，而是进入独立表格；
8. 页面通知静音、去重，并在数据过期或不完整时停用；
9. 模块与“短线右侧”保持独立。
