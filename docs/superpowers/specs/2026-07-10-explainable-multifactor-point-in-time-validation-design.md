# 可解释多因子、点时数据与样本外验证设计

日期：2026-07-10

状态：待用户复核

## 1. 背景与决策

当前平台已经具备全市场扫描、短线右侧、错杀估值、周期试仓、财务历史、估值历史、公告证据和多 Agent 讨论等能力，但推荐链路仍有几个基础问题：

- 全 A 行情分页和深度复核预算不一致，实际覆盖数量可能小于请求数量。
- `VALUE`、`CYCLE`、`SHORT_TERM` 尚未真正形成不同的资格门槛。
- 长线初筛的财务分仍主要依赖 PE、PB 和行业代理，不能稳定识别价值陷阱。
- 短线财务指标存在小数比例和百分数阈值混用的风险。
- 热门方向主要依赖静态关键词，不能及时发现新行业轮动。
- 推荐分、证据完整度、历史命中率和 Agent 共识混在一起，容易把排名分误解为成功概率。
- 回测尚未覆盖点时财务数据、历史全市场截面、完整交易约束和滚动样本外验证。

本设计选择“可解释多因子 + 点时数据 + 样本外验证”路线。第一阶段不引入黑盒机器学习荐股；所有推荐先由可审计因子、硬风控、历史验证和组合纪律生成。大模型与 Agent 只负责证据抽取、反证搜索和研究解释，不能直接绕过规则产生买卖动作。

本设计修订 `2026-07-08-universal-ashare-screener-design.md` 中两项假设：

- 统一全 A 层只共享证券主数据、可交易状态和数据质量，不再让所有策略共享盈利、横盘、PE/PB 硬过滤。
- 长期横盘只在短线“无突破”场景中排除；长线价值和周期策略将其视为时机因子，不作为通用硬风险。

## 2. 目标

- 每个交易日覆盖沪深北全部普通 A 股，并能证明实际覆盖数量、缺失数量和失败原因。
- 长线和短线使用独立算法、独立标签周期和独立验证标准。
- 财务、行情、行业、公告和政策数据都保留“当时何时可见”的点时信息。
- 所有因子都有定义、单位、方向、缺失处理、归一化方法、来源和版本。
- 所有推荐都有策略版本、数据截止时间、推荐期限、失效条件、证据和后续结果。
- 规则可通过页面调整，但必须先验证、再发布、可回滚；发布后通过 Nacos 热更新。
- 把回测结果内化到推荐详情，不恢复独立且难理解的回测页面。
- 保持 Java 17 + Spring Boot 3 + React 技术路线，核心算法可由用户直接核查。

## 3. 非目标

- 不做自动下单或无人值守实盘交易。
- 不承诺任何因子、Agent 或回测能够保证未来收益。
- 第一阶段不使用 LLM 输出作为数值因子，也不训练端到端荐股模型。
- 第一阶段不拆成大量微服务；先在模块化单体内建立稳定的数据契约和验证闭环。
- 不把论坛观点、媒体情绪或所谓“主力意图”直接当作事实证据。

## 5. 点时数据设计

### 5.1 点时原则

每条可参与评分的数据必须保留：

```text
effective_at    数据对应的业务时间
available_at    市场参与者最早可获得该数据的时间
ingested_at     平台实际入库时间
source          数据来源
source_version  来源版本或请求指纹
quality_status  VERIFIED / SINGLE_SOURCE / STALE / CONFLICT / MISSING
```

回测只能读取 `available_at <= decision_at` 的记录。财报按实际公告时间生效，不能按报告期末日期提前使用；更正公告生成新版本，不能覆盖历史版本。历史股票池必须包含当时上市、后来退市的股票，避免幸存者偏差。

### 5.2 核心数据表

```text
security_master_history       上市、退市、ST、板块和交易状态历史
trade_calendar                交易日与交易阶段
daily_bar_raw                 不复权 OHLCV、成交额、停牌标志
adjustment_factor             复权因子，前复权价格按查询截止日动态计算
quote_snapshot                盘中、15:00、15:20、15:31 快照
financial_statement_snapshot  三大报表、报告期、公告时间、版本和更正标志
financial_metric_snapshot     从点时财报派生的标准化财务指标
industry_membership_history   行业归属及生效区间
corporate_action              分红、送转、回购、增减持和解禁
filing_document               公告原文及校验信息
evidence_claim                Agent 抽取的事实、原文位置和反证状态
factor_snapshot               因子值、截面、数据版本和策略版本
market_regime_snapshot        市场状态、行业热度及其点时截面
recommendation_snapshot       推荐、动作、期限、失效条件和证据
recommendation_outcome        后续收益、回撤、是否可成交和标签
portfolio_position_snapshot   持仓、成本、计划仓位、行业暴露和生效时间
strategy_definition           策略身份、适用周期和输入输出契约
strategy_version              因子、权重、门禁、验证结果和发布状态
validation_run                回测区间、试验编号、参数、成本和结果
```

原始数据不可被派生值覆盖。比例指标在存储层统一使用小数，例如 ROE 14.26% 存为 `0.1426`；仅在页面格式化为百分数。因子定义必须声明单位，单元测试使用真实数据单位。

### 5.3 数据来源与优先级

- 证券状态、公告和风险事件：交易所、巨潮资讯和监管机构优先。
- 实时行情：保留腾讯、东方财富轮询，但每条快照必须记录来源和时间；关键动作要求行情新鲜度通过。
- 历史行情、复权因子、三大报表、审计意见、主营构成和披露日期：评估接入支持标准 HTTP 的结构化数据服务；可优先评估 Tushare Pro，Java 直接调用 REST，不要求引入 Python 运行时。
- 行业分类：采用一套稳定的主分类并保存历史归属；其他分类只作为映射。
- 政策和新闻：政府、部委、交易所和公司公告为一级证据；新闻只作为线索，必须回链原始来源。

关键数据缺失、过期或冲突时返回 `DATA_BLOCKED` 或 `EVIDENCE_REVIEW`，不能使用示例数据或旧缓存生成买入动作。

## 6. 统一全 A 资格层

统一层只负责建立可靠股票池，不直接判断价值或右侧启动。

通用检查包括：

- 标准普通 A 股代码、市场和上市状态有效。
- 本轮扫描数量与证券主表对账，分页不能静默少取。
- ST、退市整理、长期停牌和实时价格异常明确标记。
- 行情时间戳、交易阶段和来源可用。
- 每只股票保留进入或离开策略池的完整轨迹。

策略资格门槛分别处理：

```text
LONG_VALUE
  允许长期横盘；持续亏损进入 TURNAROUND_RESEARCH，不进入核心长投买入池。

SHORT_RIGHT_SIDE
  要求 20 日成交额中位数通过；长期横盘且没有有效突破时排除。

CYCLE
  允许 PE 为负或高于普通阈值，但必须有可验证的价格、产能、库存或成本周期证据。

ALL
  只展示资格和数据质量，不产生统一买入动作。
```

原有 `mode` 必须真正路由到不同策略资格实现，不能只作为响应字段返回。

## 7. 因子标准化与解释契约

每个因子由 `FactorDefinition` 描述：

```text
code
name
description
value_unit
direction
required_fields
lookback
availability_rule
missing_policy
normalization
winsorization
applicable_industries
version
```

截面因子默认流程：

1. 按点时股票池计算原始值。
2. 按 1%/99% 分位缩尾；样本不足时使用中位数绝对偏差方法。
3. 在二级行业内计算百分位或 Z 分数。
4. 必要时做市值中性化，避免单一市值风格支配结果。
5. 缺失值不按 0 分处理，而是降低 `dataConfidence` 并进入证据门禁。
6. 保存原始值、处理后值、截面样本数和排名。

必须区分：

```text
rankScore          当前截面排序分，不是成功概率
dataConfidence     数据和证据完整度
historicalHitRate  相同信号在样本外的历史命中率及置信区间
riskReward         预期收益与最大不利波动的历史比例
```

## 8. 长线价值算法 V2

### 8.1 风险门禁

任一高严重度门禁触发时不得输出买入动作：

- ST、退市整理、重大立案或审计无法表示意见。
- 连续经营现金流显著弱于净利润且无法由业务模式解释。
- 严重债务、利息保障不足、重大商誉或应收异常。
- 控股股东高比例质押、重大减持、关联交易或财务更正风险。
- 行情、财报或公告证据不满足点时和新鲜度要求。

### 8.2 初始因子族

以下权重是待验证的首版参数，不代表已经证明有效：

| 因子族 | 初始权重 | 核心指标 |
|---|---:|---|
| 财务质量 | 30% | ROIC、ROE 稳定性、毛利/资产、经营现金流/净利润、应计项目、利润率稳定性 |
| 估值安全边际 | 25% | E/P、B/P、CF/P、自由现金流收益率、股息率、历史与同业分位 |
| 核心壁垒 | 15% | 核心产品收入占比、成本优势、客户认证、市场份额、研发与产能兑现 |
| 持续成长 | 15% | 5 年营收、利润、每股自由现金流增长及波动 |
| 资本配置 | 10% | 分红、回购、再投资回报、股本稀释和并购纪律 |
| 政策与催化 | 5% | 政策受益机制、订单和产业兑现，只加分不单独支撑买入 |

风险不通过时直接阻断，不用高政策分或成长分抵消。

### 8.3 行业估值模型

```text
普通经营企业
  E/P、CF/P、FCF yield、EV/EBIT、ROIC 和增长持续性。

银行
  PB-ROE、净息差、不良率、拨备覆盖、资本充足率和分红能力。

保险
  PB、内含价值、新业务价值、投资收益稳定性和偿付能力。

证券
  PB、净资本、经纪/投行/资管结构和市场成交额敏感度。

周期企业
  中周期利润、PB、EV/产能、成本曲线、库存和供需位置；低 PE 不自动等于便宜。

高成长或暂未盈利企业
  只进入 RESEARCH_ONLY，使用 EV/Sales、毛利率、现金消耗和单位经济性，不产生核心长投买入动作。
```

### 8.4 长线阶段与动作

```text
RESEARCH_ONLY       数据或商业模式只够研究
QUALITY_WATCH       质量通过，估值尚不便宜
PRICE_WATCH         价值逻辑通过，等待安全边际
BUILD_POSITION      允许分批建立计划仓位
HOLD                逻辑和估值仍在合理区间
TRIM                估值过热或组合暴露过高，分批降低
EXIT_REVIEW         投资假设破坏，进入退出核验
RISK_BLOCKED        硬风险阻断
```

长线买入动作至少要求风险门禁通过、财务质量可用、行业估值可比、证据完整度达标和样本外统计可用。长期横盘只影响时机和资金效率，不直接否决公司价值。

## 9. 短线右侧算法 V2

短线目标周期定义为 3 至 20 个交易日，寻找“当前市场方向中，右侧启动较早、流动性充足、未明显透支且没有基本面硬风险”的股票。

### 9.1 市场状态

`MarketRegimeService` 输出：

```text
TREND_UP  趋势上行，可正常寻找右侧启动
ROTATION  板块轮动，降低追涨上限并强调行业相对强度
RANGE     震荡，偏向回踩和低位突破
STRESS    压力环境，禁止强加仓，只保留观察或退出
```

状态因子包括主要指数趋势、全市场成交额分位、上涨宽度、位于 MA20/MA60 之上的股票占比、涨跌停家数和实现波动率。

### 9.2 动态热门方向

静态关键词只作为行业映射兜底。热门方向由全市场真实截面计算：

- 行业或主题指数 1/3/5/20 日相对全市场超额收益。
- 行业内上涨家数、位于 MA20 之上比例和创 20 日新高比例。
- 行业成交额占全市场比例、占比变化和连续性。
- 龙头数量、龙头相对强度和行业内部扩散程度。
- 政策、公告或业绩事件只作为催化证据。

样本不足或热度只持续一个交易日时，最多标记为 `EMERGING`，不能直接获得满分。

### 9.3 个股因子族

| 因子族 | 初始权重 | 核心指标 |
|---|---:|---|
| 右侧结构 | 35% | 5/20/60 日相对强度、突破位置、均线斜率、ATR 标准化距离、波动收缩、收盘位置 |
| 量能与流动性 | 20% | 分时相对量、20 日量能 Z 分数、20 日成交额中位数、换手稳定性、成交参与上限 |
| 动态方向热度 | 20% | 行业超额、宽度、成交占比、持续性和扩散度 |
| 市场状态 | 15% | 趋势、宽度、波动率和风险环境 |
| 催化与质量底线 | 10% | 业绩/订单/政策催化、最新财报硬风险和公告反证 |

PE、PB 只承担软约束和极端风险识别，不再作为短线主排序因子。固定涨幅和均线距离改为相对个股 ATR、所属板块涨跌幅制度和历史波动的动态阈值。

### 9.4 交易阶段和 15:20 信号

```text
14:57 前
  只形成候选，不把未完成日线和全天成交量直接当作收盘信号。

14:57-15:00
  收盘集合竞价价格确认，评估收盘位置、虚拟匹配量和回落风险。

15:05-15:30
  盘后固定价格阶段，价格固定为收盘价，不能继续计算价格突破。
  15:20 输出可执行的 provisional 信号，使用盘后成交量、买卖未成交申报量和订单失衡。

15:31 后
  形成最终归档快照，用于次日跟踪和历史标签，不伪装成 15:20 可获得的数据。
```

15:20 的买入类动作只有在实时源能够提供该时点的盘后累计成交量、买卖未成交申报量和准确时间戳时才可生成。任一字段缺失时降级为 `NEXT_WATCH` 或 `DATA_BLOCKED`，不能用全天总量、旧缓存或 15:31 数据推测订单失衡。

短线动作：

```text
ADD             结构、量能、市场和尾盘/盘后需求共同确认
LIGHT_TRIAL     结构进入可试错区，但证据尚未达到强加仓
NEXT_WATCH      日线值得跟踪，当日执行条件不足
WAIT_PULLBACK   已经启动但 ATR 距离或情绪过热
WAIT            结构、数据或风险条件不足
EXIT            持仓信号失效或风险触发
```

所有买入类动作必须包含计划仓位上限、失效价、建议期限和次日不能成交的处理。A 股 T+1、涨跌停、停牌、盘后固定价格和最小交易单位必须进入回测执行模型。

## 10. 统一信号与建议口径

每个策略输出 `StrategySignal`：

```text
symbol
strategyCode
horizon
asOf
expiresAt
action
rankScore
dataConfidence
historicalHitRate
hitRateConfidenceInterval
riskReward
entryPlan
invalidationRules
evidenceRefs
factorBreakdown
strategyVersion
dataVersion
```

`DecisionAggregator` 不强行把不同周期压成同一句话。例如：

```text
长线：BUILD_POSITION
短线：WAIT_PULLBACK

组合解释：长期价值允许按计划建仓，但今天短线位置不支持追价。
```

今日总建议必须结合是否持仓、当前仓位、计划仓位和行业暴露。没有持仓信息时只能输出研究动作，不能把“加仓”误用于尚未建仓的股票。

持仓按 `portfolio_position_snapshot.available_at <= decision_at` 读取。首次建立仓位使用 `LIGHT_TRIAL` 或 `BUILD_POSITION`；只有已经持仓且低于计划仓位时才允许使用 `ADD`。用户未维护持仓时，页面明确显示“未结合持仓”，不虚构成本价和仓位建议。

现有“每日信号”应聚合长线价值、短线右侧、周期和风险信号；原始筛选动作与证据门禁后的最终动作必须使用不同字段，页面只把最终动作显示为“今日建议”。

## 11. Agent 与 AI 边界

五个 Agent 保留角色，但执行不同证据计划：

```text
政策 Agent    政府、部委和产业规划原文
财务 Agent    点时三大报表、审计意见和多年序列
壁垒 Agent    年报主营、合同、客户认证、专利和产能兑现
估值 Agent    历史估值、行业同业和情景估值
风险 Agent    监管、问询、诉讼、质押、减持、关联交易和会计更正
```

每个结论必须包含来源 URL、发布日期、可见时间、原文定位、摘录哈希、支持或反证方向和置信度。找不到依据时 Agent 必须 `ABSTAIN`，不能用模型常识补分。

裁判层计算：

```text
independentSourceCount  独立来源数量
evidenceOverlap         Agent 之间证据重合度
contradictionCount      尚未解决的反证数量
freshnessScore          证据新鲜度
```

Agent 共识只能改变 `dataConfidence`、研究阶段和补证清单；数值买卖动作仍由策略、风控和组合门禁生成。

## 12. 样本外验证

### 12.1 因子实验室

每个因子发布前必须输出：

- 覆盖率、缺失率、异常值和行业分布。
- Rank IC、ICIR、分位数组合收益和单调性。
- 1/3/5/10/20 日或 6/12/24 月衰减曲线。
- 换手率、交易成本、行业和市值暴露。
- 不同市场状态、板块和年份的稳定性。

### 12.2 标签

长线标签：

```text
未来 6/12/24 个月相对中证全指和行业指数的超额收益
期间最大回撤
财务质量是否恶化
投资假设是否触发失效条件
```

短线标签：

```text
按信号规则可成交后的 3/5/10/20 日净收益
最大有利波动 MFE
最大不利波动 MAE
止损、止盈和时间退出结果
涨跌停、停牌或 T+1 导致的不可执行状态
```

### 12.3 滚动验证

- 长线首版采用至少 5 年训练、1 年验证、随后 1 年测试的滚动窗口。
- 短线首版采用至少 3 年训练、6 个月验证、随后 6 个月测试的滚动窗口。
- 参数只在训练和验证区间调整，测试结果不可反向用于本轮调参。
- 按标签周期执行 purge/embargo：训练样本的未来标签窗口不得跨入验证期，验证样本的标签窗口不得跨入测试期；6、12、24 个月和 3、5、10、20 日标签分别计算隔离长度。
- 截至回测截止日尚未成熟的标签不参与命中率和收益统计，只计入“待观察样本”。
- 每次试验记录 `trialId`，避免只保留最好结果，并计算多重试验修正后的可信度。
- 同时输出绝对收益、基准超额、最大回撤、Calmar、Sharpe、胜率、盈亏比和样本量，不以单一指标判定成功。

### 12.4 执行与成本

- 佣金、印花税、过户费和可配置滑点。
- 按成交额参与比例估算的市场冲击。
- 停牌、涨跌停、一字板和开盘跳空。
- 主板、创业板、科创板、北交所不同涨跌幅制度。
- T+1 和盘后固定价格交易规则。
- 信号当时实际可获得的价格，禁止用收盘后数据倒推收盘前成交。

15:20 provisional 信号的模拟入场仅允许使用 15:20 后盘后固定价格阶段的实际可匹配成交量；排队后未成交记为 `UNFILLED`。15:31 后生成的归档信号只能从下一交易日开始模拟，按策略版本声明的开盘价、限价或 VWAP 规则执行，不能回填当日收盘价。

### 12.5 发布门禁

策略或因子只有同时满足以下条件才可成为正式推荐依据：

- 点时、复权、退市样本和未来数据测试全部通过。
- 样本外方向在大多数滚动窗口一致，不依赖单一年份或行业。
- 扣除成本后相对基准仍有正向贡献。
- 参数在合理邻域内稳定，不依赖单个精确阈值。
- 样本量和置信区间在页面明确展示。

未通过时可以保留为研究实验，但不能影响买入动作。

## 13. 规则配置、发布与回滚

规则编辑仍在页面完成，但权威版本存入数据库：

```text
DRAFT -> DATA_CHECK -> FACTOR_TEST -> WALK_FORWARD_TEST
      -> APPROVED -> PUBLISHED -> RETIRED
```

- 每次变更生成不可变 `strategy_version`。
- 数据库保存因子定义、权重、门禁、验证结果、操作人和原因。
- Nacos 只保存当前激活版本 ID、运行参数和热更新通知。
- 推荐快照保存实际使用的策略版本和数据版本。
- 发布失败时继续使用上一已验证版本，不能自动切到草稿。
- 支持一键回滚，回滚同样记录审计日志。

配置分为两类：

```text
决策参数
  因子、权重、阈值、资格门槛和动作映射。必须生成新策略版本并完成样本外验证后发布。

运行与紧急风控参数
  数据源开关、超时、并发、新鲜度上限、停止买入和仓位上限。可由 Nacos 实时生效并写审计日志。
```

紧急参数可以立即收紧风险，但不能绕过验证放宽买入条件；恢复或放宽条件必须走版本审批。

## 14. 调度与性能

- 全市场原始数据和常用因子批量入库，页面不再逐只发起 N+1 远程请求。
- 每日收盘后生成完整 EOD 因子；盘中短线只叠加实时行情和分时增量。
- 14:57、15:00、15:20 和 15:31 使用独立快照类型，互不覆盖。
- 外部数据源使用有界线程池、限速、重试、熔断和独立超时，禁止阻塞任务进入公共 `ForkJoinPool`。
- 批处理记录总股票数、成功数、缺失数、重试数、耗时和数据截止时间。
- 页面只读取已完成且版本一致的推荐快照；正在计算时展示任务进度，不返回示例候选。

## 15. API 与页面

建议新增稳定接口，并保留现有接口兼容适配一段时间：

```text
GET  /api/strategies/long-term/report
GET  /api/strategies/short-term/report
GET  /api/strategies/{code}/versions
POST /api/strategies/{code}/validate
POST /api/strategies/{code}/publish
POST /api/strategies/{code}/rollback
GET  /api/recommendations/{symbol}/history
GET  /api/factors/{symbol}/snapshot
GET  /api/validation/{strategyCode}/summary
```

页面原则：

- “全市场”展示真实股票池对账、数据新鲜度和策略资格，不直接给统一买入建议。
- 增加长线价值视图，展示质量、估值、壁垒、持续性、资本配置和政策催化。
- 短线右侧展示市场状态、动态热门方向、右侧结构、15:00 和 15:20 两类信号。
- 个股详情同时展示长线和短线结论，并给出不冲突的组合解释。
- 回测不恢复为独立页面；推荐详情显示样本外样本数、命中率区间、盈亏比、最大回撤和适用市场状态。

## 16. 错误处理

```text
DATA_BLOCKED       关键行情、点时财报或交易状态缺失
STALE_DATA         数据超过策略允许的新鲜度
SOURCE_CONFLICT    多源关键字段冲突
INSUFFICIENT_OOS   样本外验证不足
RISK_BLOCKED       公司风险门禁触发
EVIDENCE_REVIEW    Agent 证据缺失或反证未解决
CALCULATION_FAILED 因子或策略计算失败
```

错误必须包含股票、策略、数据截止时间、失败阶段、来源和可执行的下一步。任何错误状态都不能静默降级成买入候选。

## 17. 测试策略

### 17.1 数据与因子

- 请求 300、1000、5000 只时，实际覆盖数与证券主表对账。
- ROE `0.1426` 按 14.26%参与阈值和页面展示。
- 同一财报在公告前不可见，公告更正后保留旧版本。
- 前复权价格按查询截止日计算，不受未来复权因子污染。
- 行业分类变更只在生效日后影响行业排名。
- 缺失因子降低数据置信度，不被默认成 0 分。

### 17.2 策略

- 同一股票在 `LONG_VALUE`、`SHORT_RIGHT_SIDE`、`CYCLE` 下走不同门槛。
- 长线横盘股票可以进入价值观察，短线无突破时被排除。
- 周期股低 PE 不能单独触发低估结论。
- 动态热门方向不能因两只样本单日上涨直接满分。
- 市场处于 `STRESS` 时，短线强加仓被门禁降级。
- 15:20 信号只使用当时可见信息，不使用 15:31 数据。

### 17.3 验证和决策

- 滚动测试区间与训练区间完全隔离。
- 交易成本、T+1、停牌和涨跌停改变模拟成交结果。
- 长线建仓与短线等回踩可以同时存在，并生成正确组合解释。
- 原始筛选动作不能越过证据、风险和组合门禁成为最终建议。
- 推荐台账能够复现任一历史推荐使用的因子、规则和数据版本。

### 17.4 集成

- PostgreSQL 使用 Testcontainers 验证点时查询和版本回放。
- 外部数据客户端使用固定真实结构样本验证分页、单位和字段变更。
- 完整后端测试、前端构建和 Docker 健康检查通过。
- 多个历史交易日快照可重复回放，结果不依赖当前行情。

## 18. 分阶段实施

### P0：修正确性

- 修复全 A 分页少取和漏斗统计失真。
- 修复比例单位，建立因子单位契约。
- 让策略模式真正路由到不同资格逻辑。
- 区分原始筛选动作和最终今日建议。

### P1：点时数据与推荐台账

- 建立证券、行情、财报、行业和公告点时表。
- 建立因子快照、推荐快照和后续结果表。
- 将在线 N+1 拉取改为批量任务和版本化快照。

### P2：长线价值 V2

- 实现行业中性多因子、行业估值模型和风险门禁。
- 政策降为催化因子，横盘降为时机因子。
- 长线页面展示分项、证据、历史验证和阶段动作。

### P3：短线右侧 V2

- 实现市场状态、动态热门方向、ATR 标准化和时间归一相对量。
- 接入 15:00 收盘确认和 15:20 盘后订单失衡信号。
- 把短线财务质量改为风险底线和少量权重。

### P4：样本外验证与统一决策

- 建立因子实验、滚动回测、试验登记和组合成本模型。
- 将验证摘要内化到推荐详情。
- 每日信号聚合所有策略，并基于持仓生成总建议。

### P5：Agent 证据独立性

- Agent 按独立来源执行不同检索计划。
- 增加来源重合、反证和新鲜度指标。
- 数据和验证闭环稳定后，再评估可解释机器学习排序；模型输出仍需通过门禁。

每个阶段单独验收，不等待所有阶段完成后一次上线。

## 19. 验收标准

- 全 A 默认运行能对账到当日证券主表，任何少取都有明确原因。
- 长线财务质量来自真实多年点时数据，不再使用 PE/PB 和行业标签代理。
- 短线财务分使用统一小数单位，因子分布具有合理区分度。
- 长线、短线和周期模式对同一股票产生可解释的不同资格与结论。
- 热门方向来自动态行业截面，静态关键词不再决定热度分。
- 15:20 信号遵守盘后固定价格机制，并和 15:00 价格确认分开展示。
- 每个正式建议展示策略版本、数据截止时间、样本外统计、证据完整度和失效条件。
- 任一历史建议可通过推荐台账完整重放。
- 规则修改未经样本外验证不能发布为正式推荐依据。
- Agent 找不到证据时明确弃权，不能用模型推测补齐事实。
