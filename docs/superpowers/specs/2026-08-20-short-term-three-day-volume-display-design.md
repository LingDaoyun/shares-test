# 短线股票条目三日成交量对比展示设计

## 目标

在短线模块的每个股票候选条目上，直接展示当日成交量与此前三个交易日平均成交量的具体值，并附带两者的倍数关系，让用户无需打开详情即可判断是否出现短期放量。

本次只补充可解释展示，不改变现有 20 日量比、量能评分、候选排序或交易动作规则。

## 指标口径

对候选所使用的按交易日升序排列的日 K 数据定义：

- `todayVolume`：最新一根日 K 的累计成交量。盘中报告代表截至报告行情时点的累计量，收盘后才代表全天量。
- `averageVolume3`：紧邻最新一根日 K 之前的三个交易日成交量算术平均值，严格排除最新交易日。
- `volumeRatio3`：`todayVolume / averageVolume3`，保留两位小数。

计算必须使用最近连续三个交易日，不能跳过缺失日后向前补取其他日期。最新成交量或前三日任一成交量缺失、为零或为负时，对比结果标记为不可用，不以默认值或估算值补齐。

成交量沿用 `EastMoneyKLine.volume` 的原始“手”口径。前端只做单位缩放，不改变底层数值：不足一万手显示“手”，一万手及以上显示“万手”，达到一亿手时显示“亿手”。当日量和三日均量必须使用相同的格式化规则。

## 后端数据流

`ShortTermTechnicalSignalEvaluator` 在现有 5 日、20 日量比计算位置同步计算三日成交量对比，并把以下可空字段写入 `ShortTermTechnicalSnapshot`：

- `todayVolume`
- `averageVolume3`
- `volumeRatio3`

计算逻辑集中在后端，前端不得根据其他字段重复推导。这样手动扫描、定时快照、历史报告和后续消费者都使用同一口径。新增 JSON 字段是向后兼容扩展；读取缺少这些字段的历史报告时按 `null` 处理。

## 股票条目展示

短线候选 `CandidateRow` 增加一个紧凑指标单元：

```text
今日量 / 前3日均
128.4万手 / 96.2万手 · 1.33×
```

展示规则：

- 具体成交量是主信息，倍数放在同一行末尾作为辅助判断。
- 盘中数据仍使用“今日量”文案，但页面已有行情时点与数据截止时间用于说明累计量截止位置。
- 任一对比字段不可用时显示“成交量待补”，不显示 `0`、`NaN` 或推算值。
- 继续保留现有“20日量比”和“换手率”，本指标是新增信息而非替换。
- 不增加新的颜色阈值或买卖暗示，避免把展示指标伪装成独立交易信号。

## 边界与非目标

- 不修改 20 日量比的 `1.20-3.20` 主确认区间。
- 不把三日对比加入量能评分、硬筛选、排序或 Agent 讨论输入。
- 不新增前端 K 线请求，不在浏览器端重复计算均值。
- 不回填旧报告中不存在的三日成交量字段。

## 测试与验收

后端测试覆盖：

1. 最新量为 `300000`，前三日量分别为 `100000`、`200000`、`300000` 时，返回今日量 `300000`、前三日均量 `200000`、三日量比 `1.50`。
2. 平均值严格排除最新交易日。
3. 前三日任一成交量缺失、为零或为负时，对比字段不可用。
4. 现有 5 日、20 日量比与右侧信号结果保持不变。

前端测试覆盖：

1. 股票条目渲染“今日量 / 前3日均”、两个具体成交量和倍数。
2. 大数值按统一单位紧凑显示。
3. 历史报告缺少新增字段时显示“成交量待补”，页面不报错。
4. 现有 20 日量比、换手率和候选交互继续展示。

验收以当前工作区的后端短线聚焦测试、`ShortTermPage` 聚焦测试和前端构建结果为准；本地测试通过不等同于线上部署已生效。
