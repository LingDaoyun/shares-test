# A 股 T+1 隔夜超短 Skill 设计

日期：2026-07-21
状态：待用户书面确认后进入实施

## 1. 目标与边界

新增独立策略族 `T1_OVERNIGHT_ULTRA_SHORT`，服务“交易日 T 买入、交易日 T+1 全部卖出”的隔夜超短研究。它不替换现有 `SHORT_RIGHT_SIDE`：

- `SHORT_RIGHT_SIDE` 继续负责 3 到 20 个交易日的右侧波段。
- `T1_OVERNIGHT_ULTRA_SHORT` 只评估一个隔夜窗口，次一交易日必须生成退出动作。
- 默认每天最多给 1 个主推荐和 2 个备选；没有合格机会时必须输出 `NO_TRADE`，不能为了每日荐股降低门槛。
- 系统不连接券商自动下单。用户仍在自己的券商客户端确认价格、数量和成交结果。
- 大模型和多 Agent 只能整理证据、提出反证和解释结果，不能覆盖 Java 风控门禁或改变最终动作。

该策略的目标不是预测每次涨跌，而是在可成交、可退出、成本可控的前提下，提高 T+1 净期望值，并把失败样本持续反馈给规则版本。

## 2. 已选方案

采用用户确认的双阶段方案：

```text
14:50 预选
  扫描全 A 股，形成 1 个主候选和最多 2 个备选。
  只输出 PRESELECT，不输出已确认买入。

15:10 最终确认
  使用完整收盘、14:57-15:00 收盘集合竞价和 15:05 后盘后固定价格数据。
  只有通过数据、风险、可成交性和样本外门禁时才输出 BUY_POST_CLOSE。

T+1 09:25 起
  根据开盘集合竞价、板块强弱和可成交状态生成退出剧本。
  最迟在 T+1 当日完成退出；跌停无法成交时记录为 FORCED_CARRY。
```

选择这一方案的原因：2026 年 7 月 6 日起，沪深交易所盘后固定价格交易已扩展到全部 A 股和 ETF，交易时间为 15:05-15:30，按当日收盘价、时间优先撮合。完整收盘数据可用于最终判断，但排队不等于成交，因此系统必须记录 `FILLED`、`PARTIAL_FILLED` 和 `UNFILLED`。

## 3. 研究依据与取舍

公开短线交易经验中的“主线、龙头、分歧转一致、弱转强、惜售”只作为待验证假设，不直接变成买入规则。

纳入的可检验思想：

- 主线优先：板块强度、上涨家数、成交额扩张和相对指数强度共同确认，不能只靠新闻热词。
- 强者恒强只在市场情绪非退潮、个股未过度拥挤、收盘结构稳定时成立。
- 尾盘订单失衡和收盘位置可能包含短期信息，但必须结合流动性、价差和次日可退出性。
- 缩量上涨仅代表潜在抛压较轻。只有此前已有有效放量、当日收盘接近高位、板块同步且价格未远离均线时才加分。
- 龙虎榜和公开游资席位只用于拥挤度和次日抛压风险。已有研究观察到资金优势账户在上榜次日集中卖出的“一日游”行为，因此不能把席位买入直接当利好。

明确拒绝的做法：

- 不照搬未经验证的“大佬语录”或论坛胜率。
- 不以单一涨停、单一缩量、单一资金流入或单一 PE/PB 产生买入。
- 不使用当日收盘后才发布的数据回填 14:50 信号。
- 不把无法成交的一字涨停记为买入，也不把无法卖出的一字跌停记为已止损。
- 不根据同一段样本反复调参后再把样本内收益称为有效性。

参考资料：

- 上交所《上海证券交易所交易规则（2026 年修订）》：https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml
- 深交所《深圳证券交易所交易规则（2026 年修订）》：https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf
- 白颢睿等，《中国股票市场月频动量效应消失之谜》：https://qks.sufe.edu.cn/WorkingPaper/Details/WP2020-0016
- 高雅等，《资金优势账户可以利用投资者注意力获利吗？》：https://qks.sufe.edu.cn/J/CJYJ/Article/Details/A44c2c628-9dee-45e0-b8ab-0f112001e2d9/CN
- Zhu 等，A 股简单技术规则与交易成本研究：https://arxiv.org/abs/1504.04254
- 上海、深圳限价订单簿与次日收益研究：https://www.sciencedirect.com/science/article/pii/S0264999312004129

## 4. 总体架构

新增后端领域包 `com.aistock.research.ultrashort`，保持按业务域组织：

```text
UltraShortUniverseService
  全 A 股基础池、证券类型、上市天数、ST/退市和流动性硬过滤。

UltraShortMarketRegimeService
  市场广度、涨跌停结构、热门方向生命周期和退潮门禁。

UltraShortFeatureService
  生成点时价量、收盘结构、相对强度、基本面底线和事件风险特征。

UltraShortDecisionService
  执行硬门禁、排序、主推荐/备选选择和 NO_TRADE 决策。

UltraShortExecutionService
  评估盘后固定价格可成交性，生成 T+1 退出动作并记录无法成交状态。

UltraShortValidationService
  滚动样本外验证、成本模拟、策略晋级和降级。

UltraShortRunService
  编排 14:50、15:10 和 T+1 退出任务，持久化不可变快照。
```

现有组件复用：

- `EastMoneyClient` 的全市场行情、K 线和分时接口，但通过新的 `UltraShortMarketDataGateway` 隔离数据源。
- `TradingClockService` 的普通交易、收盘集合竞价和盘后固定价格阶段。
- `ResearchHistoryService`、推荐审计和交易回填链路。
- 现有 Agent 证据模型和统一决策 Broker，但使用新的策略代码和独立阈值。

不得复用现有 3-20 日右侧回测结论作为 T+1 有效性证明。

## 5. 点时数据与数据门禁

每次运行保存以下不可变字段：

```text
run_id
strategy_version
rule_version
decision_stage
decision_at
data_cutoff_at
provider
provider_timestamp
market_coverage
symbol_snapshot
sector_snapshot
intraday_snapshot_hash
announcement_snapshot_hash
feature_values
agent_votes
decision
blocked_reasons
```

数据新鲜度默认要求：

- 14:50 行情延迟不超过 60 秒，分时数据最后时间不早于 14:48。
- 15:10 必须取得当日正式收盘和 15:05 后盘后固定价格行情。
- 全市场有效覆盖率不低于 95%。低于阈值时整次运行 `DATA_BLOCKED`，不得使用旧缓存伪装实时数据。
- 免费行情源不能证明具备券商级实时性，页面必须显示来源、时间戳和延迟；用户下单前仍需用券商行情复核。
- 同日龙虎榜通常晚于最终决策，不进入 15:10 的同日因子；只可使用在决策时已公开的历史龙虎榜数据。

数据源采用可插拔网关和有界重试。主源失败时允许切换备源，但不同口径必须归一化并记录来源；所有来源都失败时关闭信号，不使用数据池旧结果。

## 6. 股票池硬过滤

全 A 股扫描，不使用白名单。以下条件默认直接排除：

- ST、退市整理、暂停上市或当日无法正常交易。
- 上市未满 60 个交易日或处在无涨跌幅限制期。
- 最近财报归母净利润为负，或审计、立案、重大财务更正等硬风险未解除。
- 20 日成交额中位数低于配置阈值，或当日成交额处于全市场低流动性分位。
- 一字涨停、接近涨停且买盘无法成交、盘口价差异常或盘后没有可验证卖方流动性。
- 近 20 日存在连续极端上涨、严重异常波动核查或明显高位加速。
- 次日为已知停牌、重大事项、除权除息或财报披露高风险窗口且策略没有相应历史验证。

PE/PB 不作为硬过滤。基本面在这里负责排除明显有问题的公司，不负责证明隔夜必涨。

## 7. 市场和热门方向门禁

先判断市场状态，再选个股：

```text
RISK_ON
  市场广度、成交额和短线高度健康，允许正常试仓。

STRUCTURAL
  指数一般但有清晰主线，只允许主线前排且降低仓位。

RETREAT
  涨停溢价下降、跌停增加、热点快速轮动，只输出 PRESELECT/NO_TRADE。

PANIC
  广度和可退出性显著恶化，强制 NO_TRADE。
```

热门方向分数由板块上涨广度、板块成交额变化、5 日相对强度、涨停/大涨家数、龙头持续性和新闻催化证据组成。单只股票大涨不能把整个板块判为主线。

## 8. 因子与决策规则

初始排序因子仅是待验证参数，必须由样本外结果决定是否晋级：

| 因子族 | 初始权重 | 核心内容 |
|---|---:|---|
| 收盘结构与相对强度 | 25% | 收盘位置、尾盘回撤、相对指数/板块强度、突破质量 |
| 主线和市场情绪 | 20% | 热门方向生命周期、板块广度、赚钱效应 |
| 流动性与订单承接 | 20% | 成交额、量比、盘口失衡、盘后卖方流动性、价差 |
| 次日可退出性 | 15% | 历史开盘跳空、跌停概率、波动率和拥挤度 |
| 惜售承接 | 10% | 放量确认后的缩量上涨/回踩、下跌缩量、收盘近高位 |
| 基本面和事件底线 | 10% | 盈利、现金流、公告、审计和已知事件风险 |

缩量上涨采用三态识别：

```text
POSITIVE_ABSORPTION
  先有有效放量，再缩量上涨或缩量回踩；板块同步、收盘靠近高位。

WEAK_PARTICIPATION
  突破本身缩量、板块不跟、成交额不足；不得买入。

HIGH_LEVEL_DIVERGENCE
  高位连续缩量、远离均线或出现长上影；作为拥挤风险扣分。
```

最终动作：

```text
PRESELECT          14:50 预选，尚未确认买入。
BUY_POST_CLOSE     15:10 通过全部门禁，可按盘后固定价格尝试买入。
BACKUP             合格备选，仅在主推荐未成交且自身仍通过门禁时使用。
NO_TRADE           当日没有正净期望或市场不适合隔夜。
DATA_BLOCKED       数据覆盖、新鲜度或盘后可成交性不足。
RISK_BLOCKED       公司、市场或事件硬风险阻断。
```

主推荐需要同时满足：市场不是 `RETREAT/PANIC`、数据门禁通过、风险门禁通过、执行 Agent 支持、反方 Agent 无硬否决、验证状态不低于 `EXPERIMENTAL_LIGHT_TRIAL`。

## 9. 多 Agent 共识

每个 Agent 使用独立证据，不重复读同一份结论：

```text
MainlineAgent       判断主线强度和板块生命周期。
StructureAgent      判断收盘结构、相对强度和惜售承接。
FundamentalAgent    判断盈利底线、财务异常和公告风险。
ExecutionAgent      判断 15:10 是否可买、T+1 是否有合理退出能力。
ContrarianAgent     专门寻找高位派发、龙虎榜一日游、事件和数据漏洞。
```

每个 Agent 输出 `SUPPORT/AGAINST/ABSTAIN`、证据时间、来源和失败条件。找不到证据必须 `ABSTAIN`。`FundamentalAgent` 或 `ExecutionAgent` 的硬否决不可被其他 Agent 多数票覆盖。

## 10. 仓位与 T+1 退出

由于 T 日买入后无法当日纠错，仓位是第一风险控制：

- 默认每天只允许一个新仓，不加杠杆。
- 主板单票默认上限为账户权益的 3%；创业板、科创板和北交所默认上限为 2%。
- 所有阈值在配置页和 Nacos 中可版本化调整，但每次调整都生成新规则版本并重新进入验证状态。
- 推荐必须给出信号日低点、ATR 风险和最大可接受跳空损失，不能只给目标收益。

T+1 退出引擎根据实时状态选择：

```text
EXIT_AT_OPEN
  低开跌破失效位、板块转弱或公告出现反证，首个可成交窗口退出。

TAKE_PROFIT_EARLY
  高开但承接减弱，分批止盈并在上午完成退出。

TRAIL_TO_CLOSE
  强势延续且板块同步，允许跟踪到 14:50，但当日必须退出。

EXIT_POST_CLOSE
  普通竞价未完成退出时，15:05-15:30 按固定价格继续执行。

FORCED_CARRY
  跌停、停牌等原因无法成交；记录真实风险，不伪造止损成交。
```

盘后推荐未成交时不得在 T+1 追高补买。

## 11. 回测与晋级

隔夜超短不能只用日 K 线验证 14:50/15:10 信号。系统需从上线日起持续保存分钟级点时快照，并可接入合法历史分钟数据源进行回补。

回测必须模拟：

- 14:50 和 15:10 当时真实可见数据，禁止未来函数和幸存者偏差。
- 盘后固定价格排队、部分成交和未成交。
- T+1、涨跌停、停牌、最小交易单位和无法退出。
- 买卖佣金、卖出印花税、过户费、滑点和冲击成本。
- 牛市、熊市、震荡、热点轮动、退潮和恐慌环境。
- 滚动训练/验证/样本外窗口，参数只在训练段调整。

核心指标：净胜率、单笔净期望、中位收益、盈亏比、Profit Factor、最大回撤、尾部损失、盘后成交率、跌停无法退出率、NO_TRADE 比例和不同市场状态表现。

策略状态：

```text
SHADOW
  只有影子信号，不给可执行买入。

EXPERIMENTAL_LIGHT_TRIAL
  样本和净期望初步过线，只允许默认小仓上限。

VALIDATED
  滚动样本外、成本和压力测试均通过。

SUSPENDED
  最近样本明显漂移、数据质量下降或尾部风险超限，自动停止推荐。
```

首版上线不得宣称已验证。已有日线回测只能作为结构参考，分钟级样本未积累前显示 `EXPERIMENTAL_LIGHT_TRIAL` 或 `SHADOW`。

## 12. 页面、API 与每日提醒

新增一级页面 `/#/ultra-short`，标题为“隔夜超短”。页面第一屏直接展示当前阶段：

- 14:50 前：等待预选，展示数据新鲜度和市场状态。
- 14:50-15:09：主预选、备选、阻断原因和最终确认倒计时。
- 15:10-15:30：最终动作、盘后成交条件、仓位上限和次日退出剧本。
- T+1：显示持仓对应的实时退出建议和实际成交回填。

API：

```text
POST /api/ultra-short/runs/provisional
POST /api/ultra-short/runs/final
GET  /api/ultra-short/runs/latest
GET  /api/ultra-short/runs/{runId}
POST /api/ultra-short/exits/evaluate
GET  /api/ultra-short/validation/latest
```

应用内部定时任务在交易日 14:50、15:10 和次日 09:25 运行并持久化。另建立 Codex 工作日提醒：14:50 发预选，15:10 发最终推荐或明确空仓，次日 09:25 对上一交易日已回填成交的股票给退出建议。应用不可用或数据不达标时只发送故障/空仓说明。

## 13. 配置与审计

Nacos 增加 `ultra-short-t1` 配置段，至少包含：

```yaml
ultra-short-t1:
  enabled: true
  strategy-version: t1-overnight-v1
  provisional-cron: "0 50 14 * * MON-FRI"
  final-cron: "0 10 15 * * MON-FRI"
  exit-cron: "0 25 9 * * MON-FRI"
  minimum-market-coverage: 0.95
  maximum-quote-delay-seconds: 60
  main-board-position-limit: 0.03
  high-volatility-board-position-limit: 0.02
  maximum-daily-picks: 1
  maximum-backups: 2
```

运行记录必须保存配置快照和版本，确保历史推荐可复现。页面调整配置时校验范围、记录操作者和时间，并允许回滚，但不允许无版本热改历史记录。

## 14. Skill 交付物与测试

仓库新增 `skills/a-share-t1-overnight/SKILL.md`，用于指导 AI 在每日任务中调用平台数据、执行证据门禁并输出统一格式。Skill 不复制 Java 算法，只声明：何时调用、需要哪些数据、遇到缺失如何阻断、怎样解释和怎样生成次日退出计划。

按照 Skill TDD 先运行无 Skill 的压力场景，记录基线错误，再验证新 Skill 能阻止以下行为：

- 市场退潮仍强行推荐一只股票。
- 把缩量上涨直接解释为惜售买点。
- 使用过期行情或昨日分时作为实时尾盘证据。
- 把一字涨停记为可买，把跌停记为已止损。
- 大模型多数票绕过财务或执行硬否决。
- 盘后未成交却在次日把推荐记为成功交易。
- 只汇报胜率，不计交易成本、未成交和尾部损失。

## 15. 验收标准

- 新策略与现有短线右侧完全分离，策略代码、规则版本、持有周期和回测互不混用。
- 全 A 股无白名单扫描，硬风险和数据不足股票不展示为推荐。
- 14:50 只给预选；15:10 才能给最终动作；无机会时稳定输出 `NO_TRADE`。
- 页面、API、历史记录和每日提醒展示同一个最终动作，不再出现“一个模块加仓、另一个模块观望”。
- 所有推荐包含数据截止时间、行情来源、市场状态、因子拆解、Agent 分歧、可成交条件、仓位上限和次日退出剧本。
- 回测包含成本、T+1、盘后固定价格、涨跌停和无法成交；样本不足时不宣称有效。
- 用户回填实际买卖时间和价格后，系统自动计算收益，并按策略版本进入反馈统计。
