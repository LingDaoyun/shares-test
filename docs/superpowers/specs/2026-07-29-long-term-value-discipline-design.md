# 长期价投质量与估值纪律设计

日期：2026-07-29

状态：用户已确认实施

## 1. 目标

把“选标的、定价格、控仓位、等兑现”的价值投资流程纳入长期价投模块，但不把
ROE 15%、内在价值 70%、下跌 15% 加仓等经验数字写成全行业统一硬门槛。

长期价投结果必须回答：

- 公司多年盈利和现金质量是否持续；
- 当前行业应使用哪一种估值模型；
- 当前价格隐含了什么增长或资本回报预期；
- 哪些证据支持安全边际，哪些数据仍缺失；
- 什么情况下允许建仓、复核加仓、暂停加仓或退出；
- 后续季度、年度和重大事件需要审计什么。

## 2. 设计原则

1. 全 A 统一池只做交易资格、数据质量和重大风险硬排除，不按 PE/PB/ROE 一刀切。
2. 长期价投采用少量硬否决和可解释多因子排序。
3. 财务质量按行业模板解释。普通企业、周期行业和金融行业不得共用同一阈值。
4. 反向 DCF 是市场预期诊断，不是精确目标价承诺。
5. 缺少资本开支时只能使用经营现金流和利润代理，并明确标记模型置信度和数据缺口。
6. 股价下跌只触发逻辑复核，不能自动触发加仓。
7. AI 负责证据抽取和反证搜索；确定性评分、风险门禁和仓位纪律由 Java 规则执行。

## 3. 行业模型

### 3.1 STANDARD

适用于普通制造、消费、医药和大多数非金融企业。

- 质量重点：五年 ROE 中位数、ROE 持续性、经营现金流/利润、多年毛利率稳定性。
- 估值重点：经营者收益代理反向 DCF、市场隐含增长率和正常增长证据区间。
- 初始安全边际：25%，只作为研究参数。

### 3.2 CYCLICAL

适用于农业养殖、资源、钢铁、化工、建材、航运等周期行业。

- 质量重点：完整周期内包含亏损年份的平均盈利、正现金流年份、成本和资产负债表抗压证据。
- 估值重点：标准化盈利反向 DCF，不使用单年 PE 代表正常盈利。
- 初始安全边际：35%，并要求供需、价格、库存和产能证据。
- 牧原等历史讨论股票只能作为回归场景，不能获得代码白名单或额外分数。

### 3.3 FINANCIAL

适用于银行、保险、证券和多元金融。

- 不使用普通企业的经营现金流/净利润门槛。
- 使用 PB-ROE/剩余收益代理，倒推当前 PB 隐含的长期 ROE。
- 仍需补充不良率、拨备、资本充足率、偿付能力或净资本等行业数据。
- 初始安全边际：20%，但证据缺失时关闭买入闸门。

## 4. 因子结构

长期价投综合分采用以下初始研究权重：

| 因子 | 权重 | 当前可审计输入 |
|---|---:|---|
| 盈利质量与现金含金量 | 30% | 五年 ROE 中位数、达标年份、正现金流年份、现金/利润代理、毛利率波动 |
| 行业地位与护城河 | 25% | 同业营收排名、行业资产属性、可核验的份额/成本/品牌证据 |
| 估值隐含预期 | 25% | 反向 DCF 或 PB-ROE、正常增长/ROE 证据、价值区间、安全边际 |
| 资本配置 | 10% | 连续现金分红、股息率、盈利留存回报代理 |
| 风险与证据质量 | 10% | 年度样本、数据缺口、盈利和现金流异常、来源完整度 |

缺失数据不按 0 分伪装成差公司，而是降低证据质量分并列出补证清单。重大违法、
非标审计意见、偿债危机等硬风险由既有风险门禁处理。

## 5. 反向估值

### 5.1 普通企业和周期企业

在严格自由现金流尚未接入前，使用每股经营现金流与 EPS 的保守值构建“经营者收益
代理”。普通企业五年样本取中位数；周期行业强制使用包含亏损年份的完整周期平均，
不得只对盈利年份取中位数。

模型采用十年显式期和终值：

- STANDARD：折现率 10%，永续增长率 3%；
- CYCLICAL：折现率 11%，永续增长率 2%；
- 对隐含增长率在 -10% 到 30% 之间求解；
- 正常增长证据来自多年营收增速中位数，并限制在可解释区间；
- 输出悲观、基准、乐观价值区间和当前价格相对基准值的折价。

页面必须显示“经营者收益代理”，并列出“缺少资本开支，不能视为严格自由现金流”。

### 5.2 金融行业

使用 `PB = (ROE - g) / (r - g)` 的可审计代理关系：

- 折现率 10%，长期增长率 3%；
- 根据当前 PB 倒推隐含 ROE；
- 根据多年 ROE 中位数和 BPS 计算悲观、基准、乐观价格区间；
- 页面显示“PB-ROE/剩余收益代理”，不显示为普通 DCF。

## 6. 建仓与加仓纪律

- 系统默认单票组合上限继续采用现有 10%，文章中的 20%只作为可配置上限参考。
- 前五大持仓合计上限保留为 50%的组合规则建议。
- 初次建仓使用小比例分批计划，不因单日价格变化自动加仓。
- 下跌 15%只生成“强制逻辑复核”事件。
- 允许加仓必须同时满足：原逻辑未证伪、安全边际扩大、现金流/负债未恶化、
  行业竞争未发生不可逆变化、没有新的治理红旗。
- 估值高于价值区间时先产生减仓提示，不强制使用统一 120%阈值。

## 7. 逻辑审计

- 每季度轻审计：盈利、现金流、毛利率、负债和行业数据。
- 每年深审计：护城河、管理层资本配置、竞争格局和估值正常化。
- 事件触发审计：业绩预告、审计意见、重大并购/扩产、监管处罚、债务再融资、
  大股东质押/减持和行业供需突变。
- 卖出以核心投资逻辑证伪、治理/偿债硬风险或严重高估为依据。
- 卖出后允许重新研究和进入，不设置“永不回头”的非理性限制。

## 8. API 与页面

`MarketScanCandidate` 新增 `longTermAssessment`：

- 模型名称、策略版本、综合分和状态；
- 财务质量快照；
- 估值预期快照；
- 五维评分；
- 建仓纪律；
- 逻辑审计计划；
- 支撑证据、风险和数据缺口。

长期价投详情弹层新增：

- 行业估值模板和模型置信度；
- 五年 ROE/现金含金量；
- 隐含增长率或隐含 ROE；
- 悲观、基准、乐观价值区间；
- 当前安全边际；
- 加仓前提、证伪条件和审计日历。

现有 PE/PB、Agent 共识、同业对比和交易录入功能保持不变。

## 9. 验证

- 普通企业不因五年中某一年 ROE 低于 15%被硬排除。
- 高杠杆或现金转化差的高 ROE 企业不能仅靠 ROE 获得高质量分。
- 周期企业使用标准化盈利，不因负 PE 被普通估值淘汰。
- “进入建仓复核”必须达到对应行业模板的目标安全边际；资本开支、债务、周期供需或
  金融核心指标未补齐时只能显示“证据待补”。
- 持仓跌幅、财报披露和事件触发在自动调度落地前必须标成规则清单，不能伪装成已执行。
- 银行输出隐含 ROE，不输出普通企业反向 DCF。
- 下跌 15%只触发复核，不直接输出加仓。
- 数据不足时模型状态降级，页面明确显示缺口。
- 后端单元测试、完整 Maven 测试、前端测试与构建通过。
