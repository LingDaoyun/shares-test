# 全系统二级详情浮层设计

## 目标

将现有列表右侧常驻详情统一改造成按需打开的二级详情浮层。列表恢复为全宽，用户点击条目后查看完整详情；点击浮层外遮罩、关闭按钮或按 `Esc` 关闭。

## 改造范围

本次覆盖四个存在“选中条目后显示右侧详情”的页面：

- 短线右侧：候选股票详情。
- 全市场扫描/长期价投：候选股票详情。
- 特别关注：主动分析结果和决策历史。
- 交易复盘：复盘单详情。

设置页、规则页和页面内普通信息卡片不改造成浮层。新增成交、编辑成交、取消计划等操作型对话框保留，并允许叠加在详情浮层之上。

## 统一交互

### 打开

- 数据加载完成后不自动打开第一条详情。
- 点击可交互列表行打开对应详情。
- 键盘聚焦列表行后，按 `Enter` 或空格同样打开。
- 打开时记录触发元素，用于关闭后恢复焦点。

### 关闭

- 点击详情浮层以外的遮罩空白处关闭。
- 点击右上角关闭图标关闭。
- 按 `Esc` 关闭当前最上层浮层。
- 点击浮层内部、选择文本或滚动内容不得误关闭。
- 存在更高层级的操作对话框时，先由操作对话框消费关闭动作，详情浮层保持打开。

### 布局

- 桌面端浮层最大宽度约 `1180px`，最大高度约 `88dvh`，页面中央显示。
- 移动端保留窄幅外边距，宽度接近视口，高度不超过 `92dvh`。
- 浮层标题栏吸顶，正文独立滚动，关闭按钮始终可见。
- 背景遮罩使用中性半透明色，不使用强渐变或高亮装饰。
- 列表页面移除原右侧详情列，候选列表或表格使用完整内容宽度。

## 组件架构

新增通用 `DetailOverlay` 组件，负责：

- 通过 portal 渲染到 `document.body`，避免父级层叠和裁切影响。
- 遮罩点击判定、`Esc` 监听、背景滚动锁定。
- 初始焦点、焦点约束和关闭后的焦点恢复。
- 标题、副标题、顶部操作区、关闭按钮和可滚动正文框架。
- 统一的层级、尺寸和响应式样式。

各业务页面继续拥有自己的详情内容组件，只将内容装入 `DetailOverlay`。业务数据、评分、操作按钮和分析逻辑不迁入通用组件。

## 页面改造

### 短线右侧

- 删除候选列表与 `450px` 右侧详情的双栏布局。
- 候选列表全宽展示。
- 点击候选设置当前股票并打开浮层。
- K 线、金叉、尾盘、Agent 证据、回测等现有详情完整保留。

### 全市场扫描/长期价投

- 删除候选列表与 `430px` 右侧详情的双栏布局。
- 候选列表全宽展示。
- 估值、基本面、策略共识和证据链完整保留在浮层内。

### 特别关注

- 关注列表使用完整宽度。
- 点击股票后打开详情并按现有逻辑加载决策历史。
- 主动分析、刷新、取消关注等行为保持不变。
- 取消关注若删除当前条目，同时关闭对应详情。

### 交易复盘

- 复盘表格使用完整宽度，不再保留粘性右侧栏。
- 点击复盘单打开详情；详情异步加载期间在浮层内显示加载状态。
- 加载失败时浮层保持打开并显示错误，列表仍可操作。
- 新增/编辑成交和取消计划对话框叠加于详情浮层之上。

## 状态与数据流

- 页面保留 `selectedId/selectedSymbol` 作为当前详情标识；`null` 表示浮层关闭。
- 不再用 effect 自动选择数据集合的第一项。
- 当刷新后的数据中不存在当前标识时，自动关闭浮层。
- 关闭浮层不清除已经加载的业务缓存；再次打开同一条目可立即显示并按既有规则刷新。
- 页面切换或组件卸载时，通用组件恢复背景滚动状态。

## 可访问性

- 使用 `role="dialog"`、`aria-modal="true"` 和可关联的标题。
- 打开后焦点进入浮层；`Tab` 不应进入被遮罩的背景页面。
- 关闭后焦点返回原列表行；若触发元素已被删除，则返回页面内合理位置。
- 关闭按钮具有明确的 `aria-label` 和可见焦点状态。

## 错误处理

- 同步已有页面错误提示，不因浮层改造吞掉请求失败信息。
- 异步详情请求使用当前选中标识校验结果，避免快速切换时旧请求覆盖新详情。
- 操作进行中不自动关闭浮层；操作成功后的关闭行为沿用各业务现状。

## 验证

- 通用组件测试：遮罩关闭、内部点击不关闭、`Esc`、焦点恢复、滚动锁定。
- 页面测试：四个页面不自动打开详情，点击行打开，数据项消失时关闭。
- 交易复盘测试：加载、失败和嵌套操作对话框层级。
- 前端完整测试与生产构建。
- Playwright 或浏览器实测桌面和移动端：无横向溢出、详情可完整滚动、背景不可滚动、外部点击可关闭。

## 非目标

- 不修改后端接口、推荐算法、评分、筛选和缓存逻辑。
- 不将详情改造成可分享的独立 URL。
- 不改变现有操作型确认框和表单的业务规则。
