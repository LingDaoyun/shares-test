# 数据库迁移收口与首板完整性门禁设计

## 1. 目标

本次修复收口 H2 到 PostgreSQL 迁移及首板持久化中已经确认的五类风险：不完整数据被发布为 `READY`、迁移校验证据未持久化、备份文件权限过宽、PostgreSQL 迁移验证可静默跳过，以及遗留 schema/文档与 PostgreSQL 单库事实不一致。

修复遵循最短真实路径：不重构其他业务模块，不创建第二套迁移框架，不连接或改动当前数据库，不启动服务，不执行迁移、测试或构建。

## 2. 方案选择

采用应用层与数据库层共同 fail-closed 的纵深最小修复：

1. Java 服务只允许完整股票池进入 `READY`。
2. Flyway V3 修正既有不安全状态并约束后续写入。
3. 本地备份权限收紧并生成可复核的 SHA-256/恢复清单。
4. 提供显式 PostgreSQL 迁移验证入口；要求验证时凭据缺失必须失败。
5. 删除废弃 schema 副本并修正文档。

不采用仅修改 Java 的方案，因为它不能阻止后续代码或受控 SQL 写入非法 `READY`。本次也不执行在线数据库迁移或恢复演练，因为运行验证仍由用户掌控。

## 3. 首板数据完整性

### 3.1 应用门禁

首次历史补齐必须满足以下条件才能保存 `READY`：

- `expected_symbol_count > 0`；
- `written_symbol_count == expected_symbol_count`；
- `failed_symbol_count == 0`；
- 涨停池确认完成；
- `bar_data_version` 已生成。

任一股票补齐失败时，本轮保存为 `FAILED`，保留完成数和失败数，设置下一次重试时间，不发布部分候选。收盘日增量沿用同一完整性语义。

### 3.2 Flyway V3

新增版本化迁移，不修改已经发布的 V1/V2：

1. 将不满足完整性条件的历史 `READY` 行改为 `FAILED`，清空 `completed_at` 和 `bar_data_version`，设置可立即重试的 `next_retry_at`，并写入受长度限制的修复原因。
2. 为 `first_board_market_day` 增加状态一致性约束：
   - `READY` 必须全量写入、零失败、涨停池完成、版本和完成时间非空，且不得保留重试时间或错误摘要；
   - `FAILED` 必须有失败数、重试时间和错误摘要；
   - `IMPORTING` 不得带完成时间或版本。

迁移不删除日线、基线或业务历史。既有不完整 `READY` 只降级为可重试状态。

## 4. 迁移证据与备份安全

为现有 H2 和 PostgreSQL 备份生成一个工程内忽略的审计清单，记录：

- 绝对路径、大小、修改时间和 SHA-256；
- 备份用途及对应迁移阶段；
- 当前能够确认和无法追溯的校验边界；
- H2 回退与 PostgreSQL V2 前恢复的命令模板；
- 恢复前必须停止 API 写入且不得覆盖现库的安全提示。

目录权限设为 `0700`，备份和清单设为 `0600`。清单不得输出数据库密码、API Key 或 `payload_json`。

由于原一次性搬运工具和逐表输出未保留，本次不伪造历史行数或摘要；清单会明确标记这部分证据仍不可追溯。

## 5. 迁移验证入口

保留现有可选集成测试，增加显式验证脚本。脚本在调用 Maven 前检查 `AISTOCK_TEST_JDBC_URL`、`AISTOCK_TEST_DB_USERNAME`、`AISTOCK_TEST_DB_PASSWORD`，任一缺失立即非零退出；凭据齐全时只运行 PostgreSQL Flyway 迁移测试。

这样普通开发测试仍可不依赖数据库，但正式迁移验证不会把“测试跳过”误报为验证成功。

本次只增加测试和脚本，不执行它们。

## 6. 单一结构来源与文档

- 删除未被运行时挂载且与 Flyway 严重漂移的 `infra/db/init/001_schema.sql`。
- README 不再把该目录描述为可用结构入口。
- `docs/runtime-config.md` 统一描述 PostgreSQL 单库，删除 H2 和 `api-data` 旧说明。
- 增加备份恢复边界和显式迁移验证命令说明。

## 7. 防回归检查

新增或调整测试以表达以下行为：

- 首次导入只要存在失败股票就不得返回 `READY`；
- V3 文件包含不完整 READY 降级逻辑和状态约束；
- PostgreSQL 单库配置检查不再引用遗留初始化脚本；
- 显式验证脚本不会在凭据缺失时继续执行。

依据当前工程约束，这些检查不会由 Codex 执行。交付时明确报告“代码已修改、未运行验证”，不宣称测试通过或迁移已经应用。

## 8. 交付边界

本次会修改源代码、Flyway 迁移、测试、脚本、文档和本地备份权限/校验清单。不会连接 PostgreSQL/H2、不会修改数据库状态、不会启动或重启容器、不会部署，也不会旋转可能存在的 API Key。若后续需要应用 V3 或做恢复演练，应由用户另行明确授权。
