# 短线龙头异动风险提示设计

## 背景与目标

当前短线模块能够计算单次扫描时点的市场情绪、热门方向、行业资金流和候选排序，但这些结果都是单快照判断。系统能说“现在医药较热”，却不能回答“与昨日或本日上次扫描相比，新的权重龙头或题材龙头是否突然增强”。因此，昨日候选集中在医药、今日其他市场龙头开始加速时，页面没有给出资金切换风险提示。

第一版目标是在用户点击扫描时，识别并展示“龙头异动风险”。它是一个可解释的市场背景提示，不是新的交易模型。

## 已确认的产品决策

- 同时监控两条轨道：大市值/权重龙头和题材/行业龙头。
- 使用双基准：当日已有扫描时优先对比上一次扫描；当日首次扫描对比上一交易日最后一次可靠快照。
- 使用灵敏模式：合格的新龙头明显增强即可提示，不要求原热门方向同步走弱。
- 第一版只显示风险提示，不改变候选资格、评分、排序、操作建议、仓位建议或交易计划。
- 页面必须说明提示只代表资金切换可能性，不能把时间上的同时发生表述成确定因果。

## 方案选择

采用“全市场紧凑快照差分”。每次可靠扫描都从本次统一全市场行情构造一份小型龙头快照，只保存权重观察池、前八热门方向及其龙头，不保存完整全市场原始行情。新扫描与最近可比快照做差分，产生报告级风险结果。

不采用仅复用当前热门方向的方案，因为它没有时间差分；不采用分钟级后台轮询，因为用户当前需要的是扫描时提示，持续轮询会显著增加行情请求和运行复杂度。

## 深模块及接口

在 `com.aistock.research.shortterm.leader` 下建立“龙头异动风险模块”。它的外部接口只有一个方法：

```java
public interface ShortTermLeaderRiskModule {
    ShortTermLeaderRisk evaluate(ShortTermLeaderRiskInput input);
}
```

`ShortTermLeaderRiskInput` 一次携带交易日、数据截止时间、覆盖率、全市场点时行情、当前热门方向和最终候选。调用者不需要知道基线查询、快照格式、排名归一化和触发规则。

模块内部使用快照存储 seam：生产适配器使用 Spring Data JPA，测试使用内存适配器。数据库或风险模块失败不能让短线扫描失败；`ShortTermService` 必须失败开放为 `UNAVAILABLE` 风险状态，同时保留原候选结果。

## 行情字段

东方财富全市场行情同一次批量请求增加 `f20` 总市值字段，解析到 `EastMoneyQuote.totalMarketValue`。该字段追加在 record 尾部，并保留旧构造器，避免影响现有调用方。

成交额不能直接跨时间点比较。上午累计成交额与昨日全天成交额没有可比性，因此模块只使用：

- 本次全市场成交额排名；
- 个股成交额占本次全市场成交额比例；
- 与同覆盖口径基准相比的成交额排名变化。

原始累计成交额只用于构造同一快照内的排名和占比，不直接作为昨日/今日差值。

## 紧凑快照

每个可靠扫描保存：

- `ruleVersion`：首版固定为 `short-term-leader-risk-v1-sensitive`；
- `tradeDate`、`capturedAt`；
- 权重观察池最多 50 只：代码、名称、行业、涨跌幅、成交额排名、成交额占比、总市值；
- 当前前八热门方向：方向代码、名称、热度、排名及方向内最多三只龙头的同类行情字段。

快照按规则版本隔离。规则升级后不使用旧版本快照做差分，避免阈值变化造成伪异动。

数据库表 `short_term_leader_snapshot` 只保存快照标识、规则版本、交易日、捕获时间和 JSON 载荷。索引覆盖 `rule_version, trade_date, captured_at, snapshot_id`。

## 基准选择

模块按以下顺序选择严格早于当前 `capturedAt` 的可靠快照：

1. 同一交易日最近一次扫描，标记为 `PREVIOUS_SCAN`；
2. 最近一个更早交易日的最后一次扫描，标记为 `PREVIOUS_TRADING_DAY`；
3. 两者都不存在时标记为 `INITIAL`。

首次部署或规则版本升级没有历史基准时，模块记录本次快照并返回 `BASELINE_BUILDING`。可以列出当前达到绝对强势门槛的龙头，但文案必须是“当前强势、基线建立中”，不得称为已确认异动。

全市场覆盖不可靠时返回 `UNAVAILABLE`，且不把不完整快照保存为后续基准。

## 灵敏模式触发规则

### 权重龙头

权重资格同时要求：

- 总市值位于本次有效市值样本前 5%；
- 成交额排名位于全市场前 10%，并至少允许前 20 名进入；
- 当前涨幅不低于 `+2.00%`。

有可比基准后，满足以下任一增强条件即触发：

- 上次未进入权重观察池，本次新进入；
- 同一股票涨幅相对基准增加至少 `1.00` 个百分点；
- 成交额排名相对基准提升至少 20 位。

### 题材龙头

题材资格同时要求：

- 方向位于当前前八热门方向；
- 龙头当前涨幅不低于 `+4.00%`；
- 龙头成交额排名位于全市场前 15%，并至少允许前 30 名进入。

有可比基准后，满足以下任一增强条件即触发：

- 该方向上次不存在，本次进入前八；
- 方向排名提升至少 2 位；
- 方向龙头发生更替，新龙头达到当前强势门槛；
- 同一龙头涨幅相对基准增加至少 `1.50` 个百分点。

同一股票可以分别提供权重和题材证据，但每条轨道内去重；最终最多展示三条最强信号。排序优先看涨幅增量，再看当前涨幅和成交额排名。

## 候选集中度解释

模块按候选的非空行业统计主导行业及其占比。如果主导行业占候选至少 50%，且所有异动信号行业都与该主导行业不同，则标记 `directionConflict=true`，文案提示“候选方向集中且与新异动方向不同，需防范资金切换”。

行业匹配只做标准化后的同名/包含判断。第一版不建立新的行业知识图谱，不把“方向不同”表述成“资金已经从候选行业流出”。

## 报告模型

`ShortTermReport` 在末尾增加 `leaderRisk`，旧构造器和旧 JSON 缺失该字段时默认：

```text
status = UNAVAILABLE
summary = 历史报告未包含龙头异动风险快照
advisoryOnly = true
```

`ShortTermLeaderRisk` 包含：

- 规则版本、状态、基准类型和基准时间；
- 最多三条 `ShortTermLeaderRiskSignal`；
- 候选主导行业、集中度和方向冲突标记；
- 摘要、证据说明、数据缺口；
- `advisoryOnly=true` 和评估时间。

每条信号展示轨道、股票、行业/方向、当前涨幅、基准涨幅、涨幅增量、当前/基准成交额排名、成交额占比、总市值和触发原因。

## 页面设计

在市场概览卡片组之后、候选列表之前增加不可隐藏的“龙头异动风险”卡片：

- `WARNING`：橙色醒目卡片，显示基准、候选集中度、冲突提示和信号明细；
- `BASELINE_BUILDING`：蓝灰色卡片，明确“基线建立中”，不使用已确认异动措辞；
- `CLEAR`：紧凑显示“未检测到达到阈值的龙头增强”；
- `UNAVAILABLE`：显示数据覆盖或历史兼容原因。

每张卡片固定显示“仅作风险提示，不参与候选筛选、评分、排序或交易动作”。旧前端收到缺失字段时安全降级，不影响候选渲染。

## 数据流

1. `ShortTermService` 获取本轮统一全市场行情。
2. 现有流程计算市场情绪、热门方向和最终候选，排序逻辑保持不变。
3. 报告完成前调用一次龙头异动风险模块。
4. 模块验证覆盖率，构造当前紧凑快照并选择双基准。
5. 模块计算双轨信号和候选集中度解释，保存当前可靠快照。
6. 风险结果写入 `ShortTermReport`，前端直接展示，不重新计算。

## 失败与兼容策略

- 风险快照表、JSON 解析或模块运行异常：报告返回 `UNAVAILABLE` 风险，候选扫描继续完成。
- 市值字段缺失：题材轨道仍可计算，`dataGaps` 明示权重轨道不可用。
- 热门方向缺失：权重轨道仍可计算。
- 无候选：仍可显示市场异动，但不计算候选方向冲突。
- 覆盖不可靠：不判断、不落基线，避免污染下一次扫描。
- 历史报告：通过 `ShortTermReport` 紧凑构造器默认值兼容。

## 测试与验收

后端必须覆盖：

1. 东方财富 `f20` 总市值解析及旧 `EastMoneyQuote` 构造器兼容。
2. 首次可靠扫描返回 `BASELINE_BUILDING` 并保存快照。
3. 当日第二次扫描优先使用 `PREVIOUS_SCAN`。
4. 当日首次扫描使用 `PREVIOUS_TRADING_DAY`。
5. 权重龙头和题材龙头在灵敏模式下分别触发。
6. 不要求原热门方向走弱也能触发。
7. 不直接比较跨时点原始成交额，只使用排名和占比。
8. 候选集中在医药且异动方向不同，返回方向冲突提示。
9. 覆盖不可靠时不保存基线并返回 `UNAVAILABLE`。
10. 风险模块失败不改变候选列表、评分、排序和动作。
11. JPA 适配器能正确选择同日上次和上一交易日快照。
12. 旧报告 JSON 缺失字段时安全反序列化。

前端必须覆盖 `WARNING`、`BASELINE_BUILDING`、旧报告缺失字段和候选顺序不变。最终运行后端全量测试、React 全量测试、生产构建、`git diff --check`，再重建本地 API/Web Docker 容器并验证健康状态和页面路由。

## 非目标

- 不做分钟级常驻监控或推送。
- 不预测后续资金必然流向，也不宣称板块下跌由新龙头造成。
- 不新增硬过滤、扣分、重排、自动卖出或仓位调整。
- 不保存全市场逐股原始历史快照。
- 不接入指数成分权重、Level-2、逐笔成交或新的第三方数据源。
- 不在第一版提供阈值配置 UI。
