# 短线筹码集中区域与价位展示设计

## 1. 目标

短线候选需要直接回答以下问题：

- 当前筹码主要集中在哪些价格区域；
- 最大筹码峰对应什么价位；
- 每个主要筹码区域占总筹码的比例；
- 当前价格位于主筹码区内部、上方还是下方；
- 当前价上方仍有哪些集中套牢区；
- 前期高位筹码是否已经通过换手明显消化。

筹码仍是基于成交价格区间与换手率推算的成本分布，不表述为真实股东持仓或主力真实成本。

## 2. 当前问题

现有本地模型使用近 120 个交易日、150 个价格桶计算完整筹码权重，但汇总时只保留平均成本、成本分位数、70%/90% 成本区、获利比例和上方筹码比例。完整价格桶随后被丢弃，因此页面不能展示主筹码峰和各集中区域。

页面的“单源模型”表示本地模型缺少 Tushare 外部认证，但该术语容易被理解为只有一个筹码峰。运行环境未配置 Tushare 时，本地有效结果都会进入 `SINGLE_SOURCE`，即使本地筹码分布本身完整。

当前默认激活模式为 `SHADOW`，筹码只做诊断，不影响正式推荐顺序，不符合已确认的短线排序要求。

## 3. 方案比较

### 方案 A：继续只展示成本分位数

改动最小，但不能回答筹码峰价位和主要集中区域，拒绝采用。

### 方案 B：完全依赖外部筹码接口

Tushare 可以返回成本分位和按价位筹码数据，但需要 Token 与接口权限，也存在更新时点、限流和可用性风险。它不适合作为短线扫描的强依赖，拒绝作为主方案。

### 方案 C：保留本地完整分布，外部数据只做可选认证

使用现有东方财富日 K 与换手率在 Java 内复算完整价格分布，保留并输出压缩后的价格桶、筹码峰和连续集中区域。Tushare 仅用于 T-1 交叉验证，不阻断展示或扫描。采用该方案。

## 4. 数据口径

### 4.1 本地数据

继续使用最近 120 个有效交易日：

- 开盘、收盘、最高、最低；
- 成交量、成交额；
- 换手率；
- 当前价格与数据截止时间。

每天按换手率衰减旧筹码，并将当日新增筹码按最低价、成交均价、最高价之间的三角形分布加入价格桶。完整交易日使用 `COMPLETED_BAR`，盘中追加当日暂定 K 线时使用 `INTRADAY_ESTIMATE`。

### 4.2 数据新鲜度

筹码结构允许使用最近完整交易日 T-1 数据。盘中数据完整时追加当日增量；盘中数据缺失时保留 T-1 结果并明确标注日期，不将一天延迟视为数据过期。

### 4.3 外部认证

Tushare `cyq_perf` 或后续 `cyq_chips` 只用于交叉验证。未配置、超时或限流时显示“本地估算 · 未交叉验证”，不降低本地分布的展示完整性，也不阻断短线扫描。

AKShare `stock_cyq_em` 与本地模型都基于东方财富日 K 和同类换手衰减算法，不视为独立数据源。

## 5. 完整筹码分布输出

### 5.1 价格桶

计算器保留归一化后的价格桶，并输出：

```text
price       价格
ratioPct    该价格桶占总筹码比例，单位为百分点
normalized  相对最大筹码峰的高度，范围 0-100
```

内部仍使用 150 个价格桶。API 为控制报告体积，将相邻桶确定性合并到最多 60 个展示桶，合并后筹码比例之和必须保持 100%。

### 5.2 筹码峰

局部峰定义为筹码权重不小于相邻桶，且权重达到全局最大桶一定比例的价格桶。默认最小峰值高度为最大峰的 20%，阈值配置化。

相邻或距离过近的峰合并，避免一个宽筹码峰被切成多个噪声峰。最多输出三个主要筹码峰，每个峰包含：

- `peakPrice`：峰值价位；
- `lowPrice`、`highPrice`：峰所属连续集中区域；
- `chipRatioPercent`：区域筹码占比；
- `distanceToCurrentPricePercent`：峰值距当前价；
- `positionToCurrentPrice`：`BELOW`、`AROUND` 或 `ABOVE`；
- `rank`：主峰、次峰或第三峰。

### 5.3 连续集中区域

以局部峰为中心向两侧扩展连续价格桶，直到满足任一条件：

- 桶高度低于该峰高度的 25%；
- 遇到相邻峰的分界谷值；
- 区域筹码占比达到可解释上限。

区域低价、高价、峰值价和筹码占比均来自同一组桶。重叠区域按两峰之间最低谷切分，保证同一桶不会重复计入多个区域。

主筹码区是 `chipRatioPercent` 最大的连续区域，不强制等同于平均成本或 70% 成本区。

### 5.4 上方套牢集中区

从主要区域中筛选 `lowPrice > currentPrice` 或大部分权重高于当前价的区域，输出最接近当前价的上方集中区。页面同时展示：

- 全部上方筹码比例；
- 最近上方筹码区价格范围；
- 该区域筹码占比；
- 当前价距离该区域下沿的百分比。

## 6. API 模型

`ShortTermChipSnapshot` 新增可选字段：

```text
distributionBuckets
concentrationZones
dominantPeakPrice
dominantZoneLow
dominantZoneHigh
dominantZoneChipRatioPercent
currentPricePosition
nearestOverheadZone
```

旧归档没有这些字段时仍可反序列化，页面显示“历史版本未计算完整筹码峰”，继续展示原有平均成本和分位区间。

完整筹码分布进入短线报告 JSON 与持久化快照，保证推荐顺序可追溯。报告不得输出 Tushare Token 或原始认证请求。

## 7. 页面设计

候选详情的“筹码结构”改为两部分。

第一部分直接展示决策摘要：

- 主筹码峰价位；
- 主要集中区间及占比；
- 当前价与主筹码区的位置关系；
- 最近上方套牢区及占比；
- 获利筹码和上方筹码比例。

第二部分展示横向筹码分布图：

- 纵轴为价格；
- 横向条形长度为该价格区筹码比例；
- 当前价显示明确参考线；
- 主筹码区使用低饱和绿色；
- 当前价上方集中区使用低饱和橙色；
- 其他筹码使用中性灰；
- 图表同时提供文本数据，不能只依赖颜色表达。

列表标签将“筹码：单源模型”改为“筹码：本地估算”，详情认证状态显示“本地估算 · 未交叉验证”。`VERIFIED` 显示“本地估算 · 外部数据已核验”。

## 8. 排序整合

现有资格门禁、数据质量门禁、动作层级和追高风险门禁保持不变。筹码只能改变同一动作层级内的顺序。

正式排序采用现有 V3 结构：

```text
technicalRankingScore          45%
chipStructureScore             25%
overheadPressureReliefScore    20%
buyPressureScore               10%
```

认证系数仅表达外部一致性，不再把有效本地筹码因未配置付费接口而折减为 60%。调整规则如下：

- 本地数据 `VALID` 且 Tushare 未配置或不可用：筹码贡献系数 1.00；
- 双源一致：系数 1.00，并显示已核验；
- 双源冲突：筹码贡献系数 0，显示冲突原因；
- 本地数据不足：筹码贡献系数 0；
- 外部数据为 T-1 且与最近完整交易日一致：允许认证。

Nacos 将 `activation-mode` 切换为 `ACTIVE`。排序保留 V2/V3 分差、策略版本、筹码模型版本和参数指纹，便于回测与回滚。

## 9. 配置

新增或补充以下 Nacos 配置：

```yaml
research:
  short-term:
    chip:
      enabled: true
      activation-mode: ACTIVE
      lookback-bars: 120
      price-buckets: 150
      display-buckets: 60
      max-concentration-zones: 3
      min-peak-relative-height: 0.20
      zone-edge-relative-height: 0.25
      single-source-coefficient: 1.00
      tushare:
        enabled: false
```

每个配置值必须校验范围，非法配置回退到默认值并记录不含敏感信息的告警。

## 10. 测试

### 10.1 后端单元测试

- 单峰分布输出正确峰值、区间和占比；
- 双峰和三峰能按区域筹码占比排序；
- 相邻峰按谷值切分且桶不重复；
- 上方集中区识别正确；
- 展示桶合并后总占比保持 100%；
- T-1 本地结果可用；
- 未配置 Tushare 时本地有效筹码系数为 1；
- 双源冲突和本地不足时筹码不参与排序；
- 筹码不能跨越动作层级改变顺序。

### 10.2 前端测试

- 主筹码峰、集中区、区域占比和上方集中区可见；
- 分布图显示当前价参考线和主要区域；
- “单源模型”不再作为用户文案；
- 旧报告缺少完整分布时不崩溃并显示兼容提示；
- 移动端不出现价格标签与图表重叠。

### 10.3 实际流程验证

- 后端和 React 全量测试、构建通过；
- 发布 Nacos 配置并重建 API/Web；
- 实际触发一次完整短线扫描；
- 第一页候选在同一动作层级内按 V3 排序；
- 随机核对至少三只候选的筹码桶总和、主峰区间和页面展示；
- 刷新页面读取持久化快照，不重复触发扫描。

## 11. 非目标

- 不声称筹码分布等同于真实股东持仓；
- 不声称筹码峰等同于主力成本；
- 不为启用筹码展示强制购买 Tushare；
- 不允许筹码因子绕过技术趋势、行情新鲜度、财务风险和交易执行门禁；
- 不用后验数据改写历史推荐。
