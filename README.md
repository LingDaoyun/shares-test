# shares-test

AI 股票研究与交易复盘系统，面向 A 股的长线价值研究、政策主题跟踪、短线右侧预选、特别关注、规则配置和交易复盘。系统只提供研究辅助和过程记录，不构成投资建议。

## 系统能力

```text
全 A 股数据 -> 行情/K线/财报/公告/政策 -> 规则与证据评分 -> 候选列表 -> 复盘与策略反馈
```

主要模块：

- `短线右侧`：全市场扫描右侧启动候选，结合 K 线、量能、筹码结构、资金流、财报质量和风险门禁。
- `五日观察`：观察横盘、换手提升与连续主力净流入，保留量价对照和前瞻样本，从买入日计五个交易日。替换原“潜力龙头”导航入口。
- `长期价投`：按推荐指数展示长线样本，支持公司详情、推荐理由、风险观察和证据追踪。
- `政策解读`：每天定时拉取政策源，形成可追溯的政策主题和产业影响分析。
- `公司样本`：查看公司样本列表、公司详情、公告/财报/估值/证据缺口。
- `特别关注`：用户主动关注股票后的持续跟踪与分析历史。
- `交易复盘`：把推荐加入复盘，记录买卖成交、收益结果和策略反馈。
- `规则目录`：查看和维护可配置规则。
- `系统配置`：在现有数据库中动态维护大模型与政策源配置，保存后对下一次业务调用生效。

## 快速启动

### 1. 准备环境

需要本机已有：

```text
Java 17+
Maven 3.9+
Node.js 20+
Docker Desktop
```

首次前端安装依赖：

```bash
cd apps/web-react
npm install
```

### 2. 准备 PostgreSQL

本项目只连接本机已有 PostgreSQL，不会通过 Compose 再启动一个 PostgreSQL。请先准备独立数据库和应用账号，并设置：

```text
JDBC_DATABASE_URL=jdbc:postgresql://host.docker.internal:5432/aistock
JDBC_DATABASE_DRIVER=org.postgresql.Driver
JDBC_DATABASE_USERNAME=aistock
JDBC_DATABASE_PASSWORD=本机实际密码
```

Redis 和 MinIO 如有需要仍可使用 `docker compose --profile infra up -d redis minio`。

Flyway 迁移必须使用独立测试库验证。专用入口会检查三个测试数据库环境变量，缺少任一项都会在 Maven 启动前失败，不会把测试跳过误认为验证成功：

```bash
./scripts/verify-postgres-migrations.sh
```

### 3. 配置模型密钥

复制 `.env.example` 为 `.env.local`，按实际 Provider 设置对应环境变量。不要把真实 API Key 写入 Git。模型名、Base URL 和政策源在系统配置页维护并写入数据库；API Key 也支持数据库保存，但部署环境优先使用环境变量。

### 4. 启动后端开发服务

```bash
./scripts/run-api-local.sh
```

后端默认地址：

```text
http://127.0.0.1:19080
```

健康检查：

```bash
curl http://127.0.0.1:19080/actuator/health
```

### 5. 启动前端开发服务

```bash
cd apps/web-react
npm run dev
```

前端默认地址：

```text
http://127.0.0.1:5176
```

## 基本使用流程

### 五日观察

1. 打开 `五日观察`，默认 v2 环境与主线模型、只观察主板；可切换 v1 纯量价对照。原 `#/potential-leader` 与 `#/first-board-alert` 入口也进入此页。
2. 点击 `开始扫描`。15:40 前使用上一市场交易日，之后使用当日完整日线；若显示数据准备中，等待基线准备后手动重试。
3. v2 默认查看执行条件齐备股，可展开观察与对照；先看市场风险及持续强行业，再看个股转强、量价资金与公告。v1 默认查看资金合格股；缺数据不当作零流入。
4. 在详情查看原始指标、日 K、唯一计划入场日、入场上限、失效位及第 5 日计划退出日期。开盘超出条件则情景不成交，不换日追买。
5. v2 在唯一入场日重新检查当前市场、价格及公告，通过后才能加入交易复盘，再自行填写真实成交。此操作只记账，不向券商下单。实际计划从真实首次买入日计算。
6. 在历史面板读取已保存结果，或点击更新情景结果。更新只使用本地已有日 K，不临时拉取行情；缺失日期会保留缺口。

v2 的规则、证据边界及验证见 [环境与主线版本记录](docs/five-day-context-v2-verification.md)。两版分别保存首条完整快照，历史情景结果不等于实际成交。

两版本的基础量价与五日期限沿用 `five-day-observation-v1` 的以下**研究初值，尚未证明具有盈利优势**：

| 条件 | 初始定义 |
| --- | --- |
| 横盘 | 近 10 日最高/最低价区间不超过 8%；首尾收盘变化绝对值不超过 3%；后 5 日均价较前 5 日不低于 -1% |
| 换手提升 | 近 5 日平均换手 / 此前 20 日平均换手 ≥ 1.2，近 5 日平均成交额 ≥ 5000 万元 |
| 资金条件 | 连续 5 个市场交易日数据完整，累计主力净流入 > 0，至少 3 日为正 |
| 入场边界 | 下一交易日开盘情景入场；价格不高于信号收盘的 102%，且距失效位的初始价差不超过入场价的 5% |
| 失效位 | 横盘区间最低价 × 99.5%；收盘跌破后按下一可卖出交易日开盘情景退出 |
| 五日定义 | 买入日是第 1 天，第 5 个市场交易日收盘计划退出，节假日与周末不计 |
| 成本假设 | 每种情景统一扣除往返 20 bps（0.20%）；这是费用和滑点的研究假设，不是实际账单 |

东方财富“主力净流入”是成交分单分类指标，不能证明真实主力正在吸筹，也不等于全体买入金额大于卖出金额。5% 是初始入场价差筛选上限，不是最大亏损保证；收盘触发后次日开盘可能越过失效位。

预选前先检查当前板块范围的连续 25 个市场交易日；完整缓存直接复用，缺失时整窗回补（最多 8 个在途请求），不拼接不同复权基准的价格。仍有缺失会列明；空候选且存在缺失时不保存成功快照。再按横盘振幅从小到大预选，最多复核 100 只，页面列明未复核数量。资金全缺时保留可读结果且可重扫，不固化为前瞻样本；部分缺失时保存首次快照并标记缺口。同日同范围的首个成功快照不可覆盖。

只有信号生成和保存都在唯一入场日 09:15 前完成，才纳入前瞻样本。历史窗口为最近 30 个扫描，统计对同信号日同股票跨范围去重，再比较资金完整的量价组及其资金增强子集。跨信号日股票可能重复，两组也重叠，因此这是描述性观察，不是组合回测或因果证明。

固定计划与风险退出各有独立状态、完成数和净收益；未成交、缺数据、等待退出均不记零收益。延期退出单列实际情景日期，不能称为恰好持有五天。真实成交账本保留毛收益，费用未入账；该来源不再生成旧推荐价的 T1/T5/T20 收益。

上线依赖 Flyway `V5__five_day_observation.sql` 新增观察表；已按用户追加授权在独立测试库验证迁移并部署到本机。新调度在交易日 16:00–23:40 每 20 分钟尝试保存默认主板观察，已有固化快照直接复用；17:30 更新本地情景结果。旧龙头学习调度默认关闭，兼容配置为 `research.legacy-leader-learning-enabled=true`。目前已核实交易日历仅覆盖 2026 年，跨未覆盖年度不推算五日计划。

设计与研究来源见 [五交易日观察策略](docs/superpowers/specs/2026-09-08-five-day-observation-design.md)，交付及用户自验情景见 [五日观察验收说明](docs/five-day-observation-acceptance.md)。用户于 2026-09-08 追加授权自测与部署，执行结果及边界见 [自测部署记录](docs/five-day-observation-verification.md)。

### 短线右侧

1. 打开 `短线右侧`。
2. 检查阈值配置，例如候选数量、扫描数量、K 线复核数、追涨上限、财报风险提示线。
3. 点击 `重新扫描` 发起手动扫描。
4. 查看候选列表，默认按推荐优先级排序。
5. 进入候选详情，检查推荐理由、风险观察、筹码结构、资金流和证据缺口。
6. 需要跟踪时加入 `特别关注` 或 `交易复盘`。

当前短线常用默认值：

```text
K线复核数：0（全部预选股票）
追涨上限：6.5%
扫描数量：0（全部股票）
候选数量：0（全部匹配结果）
允许休市缓存预览：关闭
```

交易日北京时间 14:00 自动扫描并保存结果。页面持续读取已保存结果，完成后统一显示右侧与横盘长上影候选，标注形态和行业。连续历史缺失时使用 4 个并发请求补齐完整名单，不再限制每轮 100 只；真实来源缺口仍明确列出。完整扫描保留既有价格、流动性、形态与市场风险筛选，并不保证所有股票成为候选。

手动扫描和定时扫描共用一份持久化结果缓存，右侧启动与横盘长上影按同一次任务整包保存、整包加载。某一侧缺失时明确展示本次缺口，不拼入上次候选；任务失败或超时保留原缓存，较早启动的任务不能覆盖较新的结果。页面显示当前结果的完成时间，各候选保留自身行情时间；两类扫描的取数时间可能不同。

交易日收盘后重跑时，源报价须属于当天且不早于15:00；长上影不再按盘中的120秒期限误判正常收盘报价。右侧还要求当日日线已返回，缺少当日日线的股票明确记入复核缺口。长上影的横盘基准仍使用此前20个交易日，不把当日形态混入历史基准。

腾讯日线的当前日最后分片使用空结束日期取得当天真实日线，再按原请求日期范围校验；历史分片仍使用明确的结束日期。手动联合扫描默认超时45分钟，以容纳全量K线复核；超时任务不会更新共享缓存。

腾讯688股票的报价和日线成交量统一从股换算为手，保留小数精度；东方财富原有手单位保持不变，避免跨来源计算三日量比时出现100倍偏差。

页顶涨停看板的涨跌家数独立更新，每轮请求完成后60秒自动刷新，分开展示源行情时间和获取时间。扫描结果保留原采集时点，市场情绪明确标为“扫描时市场情绪”；盘中扫描家数不能当作收盘家数。数据源清单范围以看板中的来源说明为准。

短线结果应重点看：

- 是否处于可执行动作层。
- 是否有主力资金流入和上方抛压缓解。
- 筹码是否主要集中在低位，且高位筹码是否被消化。
- 是否存在公告、财报、估值、行业对比等反证。

### 长期价投

1. 打开 `长期价投`。
2. 查看样本列表，列表按推荐指数排序并分页展示。
3. 点击公司卡片进入详情。
4. 阅读推荐理由、风险观察、财报质量、估值对比、公告证据和缺失证据。
5. 对需要持续跟踪的公司加入 `特别关注`。

### 政策解读

政策看板每天北京时间 08:30 自动采集官方政策和产业新闻，按标题及已取得的正文归类，再调用已配置的大模型研究未来 2–12 周主线与 1–2 周催化。Docker 服务需要保持运行；当日 08:30 后启动或唤醒会补跑，失败不循环重试。采集快照和成功研判保存在 PostgreSQL，打开或刷新页面只读取已保存结果。

使用方式：

1. 打开 `政策解读`。
2. 在产业卡片查看近期政策线索、研判摘要和阶段，点击星标保存本浏览器的关注产业。
3. 点击 `查看趋势`，在 `趋势研判 / 政策与新闻 / 上市公司 / 研判记录` 查看验证条件、原文链接、公司关联及历史证据快照。
4. `立即采集与研判` 启动后台任务，采集完成即展示新闻，随后持续更新研判进度。主题详情可单独更新研判。

默认每日优先研判最多 8 个有近期证据或长期规划正文的产业，可通过 `research.policy.daily.max-review-themes` 调整；`research.policy.daily.enabled=false` 关闭自动任务。模型密钥在系统配置中保存。模型失败保留此前成功历史，原样证据和同一模型的成功结果在 30 分钟内复用，避免重复付费。

政策源支持列表（HTML/JSON）、单篇正文（document）和长期规划正文（plan）。列表中入选的规划最多补取 4 篇正文；长期规划来源每轮重新读取，保留来源发布日期，在每主题最多 6 条信号中预留最多 2 条规划依据。来源失败仍会影响当轮覆盖，可在采集状态查看。长期规划不受近期 90 天研判门槛限制，但不会算成今日新增催化。原文片段随研判历史保存；新增或删除长期规划可在配置中心管理。

正文只使用可识别的文章容器，按产业关键词提取对应片段供页面和模型使用；未取得正文的来源仍标注为标题线索。当前覆盖既有产业分类及固态电池等细分主题，尚不是任意产业的自动发现或全网覆盖。页面提供原文入口，AI 推演与已知事实分开显示。关联公司来自真实行情候选池；主源不可用时仅政策模块使用新浪行业分类样本，每行业最多 5 家，保留出处并将缺失行情和财务留空。公司按行业匹配并约束模型输出，不代表覆盖全体上市公司或确认直接受益；电池行业归属不能证明已有固态电池业务。

### 交易复盘

1. 在推荐卡上点击 `加入复盘`。
2. 进入 `交易复盘` 页面。
3. 录入买入/卖出成交。
4. 查看持仓、已实现收益、未实现收益和阶段性表现。
5. 通过复盘结果观察策略有效性。

## 数据持久化

PostgreSQL 是唯一业务数据库，表结构只由 Flyway 管理。默认本机开发连接：

```bash
JDBC_DATABASE_URL=jdbc:postgresql://127.0.0.1:5432/aistock \
JDBC_DATABASE_DRIVER=org.postgresql.Driver \
JDBC_DATABASE_USERNAME=aistock \
JDBC_DATABASE_PASSWORD=本机实际密码 \
mvn -pl apps/api spring-boot:run
```

最终应用依赖、配置和 Compose 均不包含 H2 接入；历史 H2 物理备份只作为离线回滚证据保留。本地忽略目录 `backups/` 中的 `SHA256SUMS` 和 `MIGRATION-AUDIT.md` 记录现有备份摘要、证据缺口与隔离恢复边界，不能代替真实恢复演练。

### 首板候选池数据

- 首次运行从 `market_kline_history` 导入可复用前复权日线，只联网补齐不足 60 根的股票。
- 每个交易日收盘后只增加该交易日，并为下一交易日发布不可变技术基线。
- API 重启直接读取 PostgreSQL READY 基线，不重新拉取全市场历史。
- 当前交易日增量、历史补齐或基线只要存在失败，页面暂停推荐且不回退旧候选；Flyway 状态约束禁止不完整市场日进入 READY。
- 非交易日继续使用最近交易日收盘行情。
- 首板专用日线只保留最近 120 个交易日，基线保留最近 5 个扫描日，市场日状态保留 130 日；共享历史表不参与清理。

核心历史表包括：

```text
market_kline_history
research_analysis_history
investment_decision_history
trade_cases / trade_fills
```

## 常见问题

### 页面仍显示旧参数

先确认是否重新构建了 React：

```bash
cd apps/web-react
npm run build
docker compose up -d --build web
```

然后强刷浏览器。

### 系统配置保存后未生效

检查以下信息：

```text
GET /api/runtime-config 返回的 storage 是否为 database
对应栏目 revision 是否已增加
前后端是否连接同一个 PostgreSQL 数据库
GET /api/ai/llm-config 是否已返回新的有效模型
```

详细说明见 `docs/runtime-config.md`。

### AI 分析不可用

检查：

```text
DeepSeek Key 是否配置
provider/model/base-url 是否匹配
接口是否要求 json_object 输出
```

### 手动短线扫描很慢

短线会拉全市场行情、K 线、财报、资金流和筹码数据。默认完整扫描，首次补齐历史可能耗时较长。页面刷新只加载保存结果；交易日 14:00 由后台自动扫描，也可点击 `重新扫描` 发起手动扫描。
